# 设备端 sidecar

让 AI 员工在**另一台电脑**上动手：老板在「设备操作台」加一台设备，目标机器跑这个
脚本，后端把命令派过来，改动发生在那台机器上——不是后端那台。

单文件、只用 Python 标准库（3.10+）。目标机器不需要装依赖、不需要 clone 仓库。

## 快速开始

```bash
# 1) 老板在「设备操作台」（/device-console）点「添加远程设备」，拿到一次性接入码
# 2) 把 aieos_sidecar.py 拷到目标机器，接入（可写目录必须显式给，不给就是只读设备）
python3 aieos_sidecar.py enroll --server http://192.168.1.20:8000 \
    --code <接入码> --allow-root ~/work/project
# 3) 常驻运行（Ctrl-C 退出；退出后设备在服务端 45 秒内变离线）
python3 aieos_sidecar.py run
```

后端地址要写目标机器**能访问到**的地址：同一局域网用后端机器的内网 IP，
跨网段用内网穿透/反代后的公网地址。`localhost` 指这台机器自己，不是后端。

## 命令

| 命令 | 作用 |
| --- | --- |
| `enroll --server URL --code CODE` | 用一次性接入码换出本机设备密钥，写进配置 |
| `run` | 报心跳 → 领命令 → 过本机护栏 → 执行 → 回报，循环 |
| `status` | 测连通性，报告在线状态、能力、可写目录 |

参数：

- `--allow-root DIR`（可重复）：允许写文件的目录。**不给 = 只读设备**，
  `write_file` / `apply_patch` / 带重定向的命令都会被本地拒绝。
  `enroll` 时写回配置；`run` 时只对本次会话生效（临时放宽用的）。
  不存在或命中红线目录的会被当场拒绝/忽略并说明原因。
- `--allow-command CMD`（可重复）：只读白名单之外的额外命令，写回配置。
- `--allow-destructive`：允许命令里出现破坏性片段（默认拒绝），写回配置。
- `--wait SEC`：领命令时服务端替这台设备等多久（默认 12 秒，必须显著小于
  45 秒的在线窗口，否则命令会在等待中被服务端判离线）。

配置与设备密钥存在 `~/.aieos/sidecar.json`（0600，可用
`AIEOS_SIDECAR_CONFIG` 换位置）。服务端吊销后本机这份配置留着也无害——
领不到命令。文件覆盖前的备份在 `~/.aieos/backups/<原名>.<时间戳>.<哈希>.bak`。

## 两把锁

服务端策略管**该不该做**（三档审批 + 白名单 + 高危拦截），sidecar 管
**这台机器允不允许**。后端规则是照着它自己那台机器写的，同一条路径在设备上
可能不存在、也可能正是老板不许碰的目录，所以这里必须再判一次，绝不
「服务器说可以我就跑」。本地拒绝也会回报 `ok=false` + `denied_locally=true`
和真实原因，让老板在服务端审计里看得见，而不是默默丢命令。

本机护栏：

- **硬拒绝路径**（任何参数都不放行）：凭据与系统目录 `~/.ssh`、`~/.aws`、
  `~/.gnupg`、`~/.config/gcloud`、`/etc`、`/System`、`/usr`、`/Windows` 等；
  密钥与可执行钩子文件名 `.env`、`.pem`、`.key`、`id_rsa`、`credentials`、
  `/.git`（hook 能变成任意命令执行）。
- **可写根目录**：只有落在 `--allow-root` 里的路径才允许写。读不受此限制
  （除上面硬拒绝的红条），因为「让员工读到代码」正是这次改造的目的。
- **shell 只放行只读命令**：`ls/cat/grep/find/diff/git status/…`（见
  `READ_ONLY_COMMANDS`）。改文件走 `write_file` / `apply_patch`——有 diff、
  有备份、可回滚，不走 shell 重定向。
- **重定向按命令的工作目录判**：`ls > out.txt` 落在哪由执行时的 `cwd` 决定，
  护栏用同一个基准算相对路径，否则判的是一处、写的是另一处。没显式给 `cwd` 时
  用第一个可写根目录，其次才是 sidecar 的当前目录。
- **文件路径用同一个基准**：`read_file` / `write_file` / `apply_patch` 里的相对
  写法（页面上直接写「notes.md」）落在上面那个工作目录，不是 sidecar 的启动目录；
  `enroll` 时 `--allow-root` 一律换算成绝对路径存盘——否则「换个目录启动」
  等于悄悄换了开放的范围。
- **命令 substitution 直接拒**：`$(...)`、反引号、`${...}` 让「这条命令到底
  做了什么」无法静态判断。
- **灾难性片段再拦一次**：`rm -rf /`、`mkfs`、`dd if=`、`shutdown`、
  `drop table`… 与后端策略同一口径——设备可能跑在完全不懂 ai-eos 的机器上。

## 能力

v1 上报 `run_shell` / `read_file` / `write_file` / `apply_patch`，即「看代码 +
改代码 + 跑命令」。截图、键鼠、无障碍树依赖各系统原生工具，不在 v1 里；
报上去的能力必须真的做得到，否则后端会把命令派给一个只会失败的机器。

## 常见问题

- **「设备离线」被拒绝**：确认这边 `run` 还在跑、`--server` 是目标机器可达的
  地址、防火墙允许出站。指名远程设备时后端**绝不回落到本机**——路径在两台机器
  上含义不同，在错误的电脑上写文件比这次没做成严重得多。
- **审计里显示「未回报（超时）」**：命令派出去了但设备没交结果，多半是掉线、
  进程被杀，或 macOS 弹出了授权框等人点。日志保留「确实派给了 X 但没回报」，
  不会事后补时间戳造假。
- **写文件被本地拒绝**：该路径不在 `--allow-root` 里，或命中凭据/系统目录红条。
  前者用 `enroll` 重新接入或 `run --allow-root` 临时放宽；后者是设计如此。
- **接入码失效**：一次性、30 分钟有效，用后即焚。回设备操作台点「重新生成接入码」。
- **换机器/重装**：`~/.aieos/sidecar.json` 里的设备密钥跟着走；不用了就先在
  设备操作台吊销，那台机器的 sidecar 会立刻领不到命令。

# 步骤级验收闸门（Step Gate）使用说明

> 版本：M1（2026-11-20）｜实现：`apps/api/app/gates/`｜证据表：`workflow_step_gates`

## 一句话

给工作流的某个节点加一条**可核对的验收标准**，产出不达标就不放行；模型只负责"写"，闸门负责"查"。

## 为什么需要

此前"验收标准"（`mission.acceptance`）只是拼进提示词，没有任何代码检查它是否达成。
模型说"我已经满足了验收标准"，系统就信了——这是多 Agent 产出不可信的根源。

## 怎么配

在节点 `config` 里加 `gate`（工作流画布/JSON 编辑均可）：

```json
{
  "gate": {
    "acceptance": "1. 明确给出通过/不通过结论 2. 列出必须解决的问题",
    "assert": {
      "min_chars": 800,
      "contains": ["## 结论"],
      "min_citations": 2,
      "emits_files": 2,
      "max_duplicate_ratio": 0.15
    },
    "max_rework": 1,
    "on_fail": "fail",
    "judge_threshold": 0.6
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `acceptance` | 空 | 交模型评审的标准。留空则只跑机械断言（不花钱） |
| `assert` | `{}` | 机械断言，见下表。全部零成本 |
| `max_rework` | `0` | 返工轮数，硬上限 1。`0` = 只查不改 |
| `on_fail` | `fail` | `fail` 阻断 / `manual` 提示人工 / `observe` 只留证不阻断 |
| `judge_threshold` | `0.6` | 评审分数阈值 |
| `allow_cliche` | `false` | 允许明确的拒答/免责句式（默认禁；只做边界匹配，不判文风） |

**语义顺序**：先跑机械断言（免费），全过之后才调模型评审（花钱）。任意环节出现阻断性失败即判该节点不通过。

## 断言规则（机械，零成本）

| 规则 | 参数 | 说明 |
|---|---|---|
| `min_chars` | int | **有效字数**：CJK 逐字 + 英文逐词，空白/标点/Markdown 符号不计 |
| `max_chars` | int | 上限，防灌水 |
| `min_headings` | int | Markdown 标题数下限 |
| `contains` | string[] | 必须出现的字面串 |
| `not_contains` | string[] | 禁用语料（字面子串） |
| `matches` | {pattern: n} | 正则命中次数；`0` 表示必须不出现 |
| `max_duplicate_ratio` | float | 重复句占比上限（默认建议 0.15） |
| `emits_files` | int | 文件块**精确**数量，少一个即不过 |
| `min_file_bytes` / `max_file_bytes` | int | 单文件大小区间 |
| `json_schema` | object | 结构化产出按 schema 校验（支持 type/required/properties/items/enum 等子集） |
| `min_citations` | int | 去重链接数下限 |
| `min_source_domains` | int | 不同域名数下限（防同一链接刷引用） |
| `min_table_rows` | int | 表格数据行下限 |
| `no_ai_cliche` | — | 默认开启：只拦明确的拒答/免责句式（“作为AI，”/“我无法提供”），**带词边界**，不会误伤“作为AI企业”这类正常表述；`allow_cliche: true` 关闭 |
| `custom` | string | **白名单**内的自定义函数（`app/gates/registry.py`），禁止任意代码 |

文件块三种写法都认：`### 文件：a.py`、`【文件：a.py】`、``` ```python src/a.py ```。

**写错规则名会直接报错**（不会静默跳过）。可用 `app.gates.rules.KNOWN_RULES` 查全集。

## 三种上线姿态

1. **观察（推荐先跑一周）**：`on_fail: "observe"`。不通过只留证、不阻断。用来校准误杀率。
2. **阻断**：`on_fail: "fail"` + `max_rework: 0`。不合规就失败，缺件不放行。
3. **返工**：`max_rework: 1`。把"上一版产出 + 未过项"交回**同一个员工**在原稿上改，仍不过则失败。

自动生成（CEO 工作流）默认是第 1 种：`observe` + `max_rework: 0`，且只接收模型给出的合法断言，自创规则一律丢弃。

## 证据怎么看

`GET /executions/{eid}` 的 `gates` 字段，一条记录包含：

```json
{
  "node_key": "summary", "gate_round": 0, "stage": "mechanical",
  "checks": [{"rule": "emits_files", "expected": 2, "actual": 1, "passed": false}],
  "passed": false, "blocking": true, "degraded": false,
  "score": null, "tokens": 0, "latency_ms": 3
}
```

- `gate_round=0` 首检、`1` 返工后复检；两轮都留，首轮失败原因不会被覆盖；
- `degraded=true`：评审模型不可用（超时/无模型/解析失败），已放行但留痕；
- `tokens=0` 且 `stage=mechanical`：这轮没花钱。

## 成本

- 机械断言：0 token；
- 评审：每节点约几千 token，只在机械全过且配了 `acceptance` 时发生；
- 单执行评审总量上限 `AIEOS_GATE_TOKEN_CAP`（默认 80000），超了自动降级为"只跑机械"。

## 已知边界

- 闸门只判"标准明确要求却没做到"，不判"还能写得更好"；
- 评审模型跟随执行员工的模型绑定，不另设全局评审模型；
- `on_fail: "manual"` 目前等价于 `fail`，只是错误文案不同（转人工审批在 M3 接）。

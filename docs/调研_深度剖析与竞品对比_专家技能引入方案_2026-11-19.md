## 第一部分：项目深度剖析 —— 能不能让用户真正喜欢？

### 1.1 产品视角：三条硬伤 + 一个战略判断

**核心判断：AI-EOS 的差异化是真的，但「用户第一次感到爽」的路径太长。**

竞品把首跑时间压到了极致：Lindy 宣称「2 分钟上手、免信用卡」，Relevance $19/月即可开团队。而我们的首次可感知价值路径是：

```
注册 → 建公司 → 招员工 → 全局配模型 → 给员工绑模型 → 下指令 → 等产出 → 去产出区看
  ①       ②        ③         ④            ⑤         ⑥        ⑦         ⑧
```

八步。每一步都有流失风险。今天实测再次验证了最大的断点：**全局「模型就绪」≠ 员工已绑模型**——发消息后才报「该员工尚未绑定任何模型」，用户在第五步被绊倒，且报错来得太晚。

**P0 交互问题（不修则「喜欢」无从谈起）：**

| # | 问题 | 证据 | 修法 |
|---|------|------|------|
| 1 | 员工未绑模型是隐形地雷：列表无标记、聊天头无提示，发消息才炸 | 实测运营专员·阿岚 | 员工列表加 ⚠ 角标；聊天头黄条「未绑定模型→去绑定」；建员工向导最后一步强制选模型 |
| 2 | 空数据死页：新公司进指标中心/合规台账/审批收件箱全是空表 | 行业包未启用时 | 每个空页配「三步点亮」引导卡（行业中心一键启用→数据就来了），沿用演示公司的成功模式 |
| 3 | 首跑无引导：工作台欢迎语是静态的，没有「下一步做什么」 | 新用户视角 | 把 FirstRunTour 升级为任务清单：✓建司 ✓招人 ✓绑模型 ✓发第一条消息，完成一个亮一个 |

**P1 交互问题（决定留存）：**

4. 47 页各自为政：iframe 隔离保住了状态，代价是视觉/交互一致性——Harness 已开始统一，但 classic/页面内部还是老样子；
5. ⌘K 只搜「页面」不搜「数据」：搜「张三未结任务」「上月应收」无结果——大厂标配是全局数据搜索；
6. 通知是被动的：审批到了不推、任务完成不响，老板得自己刷；
7. 错误文案是工程师语言（「请求失败 code=500」应翻译成「服务开小差了，重试一下」）。

**P2：** 键盘流不完整（g 类跳转）、移动端 Harness 尚未做、只有暗色主题。

**让用户喜欢上的三个抓手（产品主张）：**
1. **3 分钟出第一份产出物**——演示公司已解决 80%，再压一步：注册后直接给「看 60 秒演示」按钮；
2. **进度感**——员工执行全程可视化（ChatProcessCard 已有，缺的是把它带到 Harness 右栏常驻）；
3. **每天想看一眼**——Harness 状态栏/经营页要成为老板的「早报」，这是日活的钩子。

### 1.2 工程师视角：家底与债务

**家底（领先项）：** 工具总线 MCP-native（对外 aieos.* 出站、对内统一注册+授权）；行业包数据驱动安装（工作流/指标/合规/专家一键种植）；合规台账法条级留痕；三因子敏感门禁；trace 贯穿。30 个竞品里**没有一家同时具备这四样**。

**债务（按偿还优先级）：**
1. SQLite→PostgreSQL 从未真库回归——企业交付前的最大工程风险；
2. 47 个前端页面 = 47 个独立编译单元，构建产物与 CI 时长随页面线性膨胀——Harness 若成主形态，老页面应逐步变成「iframe 遗产」，新增功能一律做进 Harness；
3. 对话历史全量拉取（无分页/增量），长会话性能会塌；
4. 前端测试 268 个偏组件单测，核心用户路径（注册→首产出）没有端到端覆盖；
5. Prompt injection：web_search 结果直接进上下文，无隔离/白名单——企业客户安全审查必问项；
6. 每租户限流/配额缺失——SaaS 计费与防滥用共用一套地基，越晚越贵。

## 第三部分：WorkBuddy / 豆包 / 千问的专家技能体系——能不能学来？【核心交付】

### 3.1 调研事实

**① 监管剧变（2026-07-15）：** 豆包、通义千问、腾讯元宝的 **C 端 UGC 智能体广场同日下线**（《人工智能拟人化互动服务管理暂行办法》施行日）。行业解读：拟人化 UGC 陪聊死，企业级工具型智能体是政策鼓励方向。
→ **战略含义：我们不做「广场」，做「企业精选技能库」——正好站在合规一边，且填补大厂撤退留下的空位。**

**② WorkBuddy（腾讯云 CodeBuddy 团队，2026-03）：** 桌面智能体工作台，多智能体并行，卖点是**精选 Skills 技能市场**（办公/编码/创意）。其公开市场已被第三方完整存档（`infometa/workbuddyskills`，455★，2026-11-11 同步）：

| 资产 | 数量 | 格式 |
|---|---|---|
| 技能包 | 295 包 / **3,507 个 SKILL.md** | SKILL.md（YAML frontmatter：name/version/description+触发词）+ references/*.md |
| 连接器 | **573 个（541 个 mcp.json）** | mcp.json = MCP server 配置 |
| 专家团队 | **429 个** | experts/包：agents/*.md（人设）+ settings.json（编排）+ 预设 Workflow（触发问法→串并行编排）+ 团队专属技能 |
| 插件 | 90（官方 60+团队 30） | plugin.json |

**③ 格式判定：** SKILL.md 就是 Anthropic Agent Skills 开放标准——**与 ZCode 自身技能体系、与我们 toolbus 的 MCP-native 架构三方同构**。连接器的 mcp.json 可直接映射为我们的连接器蓝图（行业包 integration_targets 同机制）。专家包的「人设 md + 编排 json + 触发词 Workflow」与我们的专家包+访谈引擎概念完全对位。

**④ 官方分类（295 包）：** 文档/办公 44、腾讯/企微 47、内容创作 47、技术工程 44、数据智能 43、金融投资 39、营销增长 37、行业顾问 35、法务安全 27、销售商务 17、运营人力 15、行业顾问（含 ERP 实操类，如 ircloud 经销商订货平台全链路操作技能：订单/资金/仓库/拜访/预警…）

**⑤ 钉钉打法：** 数字员工以**通讯录成员身份**承担 150+ 流程模板岗位——「按行业给现成岗位模板」的思路与我们行业包完全一致，验证方向。

### 3.2 结论：能学来，三种姿势按成本排序

| 姿势 | 做法 | 成本 | 收益 | 风险 |
|---|---|---|---|---|
| A. 格式兼容导入 | 写导入器：SKILL.md→技能库；mcp.json→连接器蓝图；experts agents/*.md→expert_templates | 2-3 天 | 一夜获得数千条真实业务技能与数百专家团队的结构化原料 | **License/品牌合规必须逐包审**；部分技能依赖外部 CLI/密钥 |
| B. 参考再创作 | 抄结构与方法论，内容自写：按我们 10 行业包定制技能，人设用职务命名 | 持续 | 干净、贴合、可商用 | 慢 |
| C. 生态卡位 | 把「行业包×技能库」做成中文企业级发行标准，开放第三方投递 | 长期 | 护城河 | 运营投入 |

**推荐组合：A 打底 + B 精修 + C 留接口。**

### 3.3 行业分类体系（技能/专家 × 行业包匹配）

```
技能库分类树
├── 跨行业通用层（装任何行业包都送）
│   ├── 办公协作（文档/表格/PPT/会议纪要）   ← WorkBuddy「文档/办公 44」为底本
│   ├── 数据分析（报表/指标解读/导出）
│   ├── 营销增长（内容/投放/私域）           ← 「营销增长 37」
│   ├── 财税通用（发票/对账/应收）
│   ├── 人力通用（招聘/绩效/入离职）
│   └── 客服销售（话术/跟单/线索）
└── 行业专属层（与 10 行业包一一对应，随包启用）
    ├── 餐饮连锁：外卖平台运营/门店排班/食安日检/会员储值
    ├── 特种设备：定检申报/制造台账/OEE 分析
    ├── 跨境电商：多平台订单归一/汇率/退货合规
    ├── 物流仓储 / 医美 / 汽修 / 教培 / 民宿 / 律所 / 建筑 …
```

**匹配规则（三级自动+一道人工）：**
1. `industry_pack.skills` 白名单——行业包声明本行业技能清单（随包自动挂载到该行业新员工）；
2. 标签自动匹配——导入时按 SKILL.md 触发词/关键词打 industry_tags，命中行业包 tag 即归入；
3. 通用层规则——命中通用层分类的全局可用；
4. 人工审核队列——低置信度/含外呼域名/含付费依赖的进队列，超管在后台放行。

### 3.4 工程设计（V6.2 系列）

**新表 `skill_registry`**（迁移 0028）：
```sql
id, source(内置|workbuddy|社区), source_id, format(skill_md),
name, description, trigger_keywords[], industry_tags[], kind(技能|连接器|专家|插件),
payload(JSON: SKILL.md 全文/agents 编排/mcp.json), license, brand_refs[],
status(draft|auto_pass|review|published|rejected), reviewer, created_at
```

**导入器（后台页 + CLI）三通道：**
1. 技能通道：SKILL.md → frontmatter 解析 → 触发词/industry_tags 提取 → 落库 → 发布后挂载到 agent_skills（员工技能体系复用现有 skill_center）；
2. 连接器通道：mcp.json → 连接器蓝图（复用行业包 integration_targets 安装机制）→ toolbus 注册预览 → 域名过 DLP 白名单审查 → 人工放行；
3. 专家通道：experts/<pack>/agents/*.md + settings.json → 映射 expert_templates（人设/技能/预设 Workflow 触发词）→ 访谈引擎可继续增强。

**发布面：** 行业中心新增「技能库」页签（按行业过滤 + 通用层），企业侧一键安装到员工；超管侧审核队列。

**度量闭环（让技能库越用越准）：** 技能调用率、触发后任务完成率、员工留存技能 TopN → 反哺排序与推荐。

**分期：**
- **V6.2.0（2-3 天）**：skill_registry + 导入器技能/连接器通道 + 行业中心技能库页签；
- **V6.2.1（2-3 天）**：429 专家团队批量转 expert_templates（按行业人工抽校 30%）+ 专家包市场页；
- **V6.2.2（2 天）**：industry_tags 自动匹配 + 审核队列 + 度量报表；
- **V6.2.3**：开放投递接口（第三方按 SKILL.md 标准投递）。

### 3.5 合规红线（必须钉住）

1. **License 逐包审**：存档仓库仅供格式研究与内部参考，商用引入必须逐包核 license、清除第三方品牌引用（qiqi/ircloud/58pic 等 brand_refs 字段记录+清洗）；
2. **拟人化新规**：技能=工具型能力，合规；专家人设**用职务命名不用真人名/拟人昵称**（「餐饮运营专家」而非「老宋」），不涉及情感陪聊；
3. **外呼安全**：mcp.json 全部域名过 DLP 白名单 + 敏感访问审计；技能正文过 prompt-injection 扫描（结合 1.2 债务第 5 条一起修）；

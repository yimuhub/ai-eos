**修复前若直接交付会发生的真实事故（均已复现）**：

1. **工作台发消息必然随机失败**（P0，实测复现）：任务执行期间与员工对话，后端抛 `database is locked` 未处理 → 500；更糟的是架构性根因——后台作业跑在临时事件循环上却共用进程级 httpx 客户端，跨循环复用 keepalive 连接导致 `Event loop is closed`（会议第一轮发言实测失败）。
2. **暂停/恢复死路**（P0，代码推演+单元验证）：LLM 执行期间点暂停，恢复后任务永久卡 RUNNING 且无 worker。
3. **协作发消息 100% 崩溃**（P0，代码实锤）：端点把 `user.id` 当 user 对象传，`AttributeError`。
4. **跨公司数据泄漏**（P1，实测实锤）：一键建团队把新公司员工绑到**别家公司**的模型上（成本算到别家头上）。

## 三、系统总览与值得肯定的部分

1. **产品完成度高**：44 个页面覆盖了"建公司 → 组团队 → 派活 → 执行 → 交付 → 复盘成长 → 治理运维"的完整闭环，中文可操作文案与空态引导质量高。
2. **核心执行链是真的**：任务创建即入队（`auto_start` + 持久队列），worker 池、CAS 状态迁移、失败落证、任务重试都经过实测工作——本次实测任务从下达到 LLM 产出结果全程 3 分钟自动完成。
3. **安全设计有基本面**：JWT 空密钥拒绝启动、refresh token CAS 轮换、SSRF 双重校验（automation 的 webhook 是全仓库最佳实践）、上传白名单 + 服务端命名、越权统一 404。
4. **双壳工作台切换忠实兑现承诺**：经典 → 极客把当前页带进右栏标签（实测 `/workflow-builder` → `/workspace?app=%2Fworkflow-builder`，iframe 正常加载，刷新还原），极客 → 经典反向亦然。
5. **部署形态齐全**：便携启动（三平台脚本）、Docker compose、服务器一键部署、桌面壳、移动 PWA（/m 三标签页正常）、设备代理配对。

## 四、发现的问题（修复前状态）

### 4.1 P0 —— 会直接事故的死胡同（3 项，全部已修）

| 编号 | 问题 | 实测证据 | 修复 |
|---|---|---|---|
| **B-106** | **进程级共享 httpx 客户端 × 临时事件循环 = 随机 `Event loop is closed`**。`submit_async` 在 worker 线程用 `asyncio.run()` 开临时循环跑每个后台作业，而模型网关的 AsyncClient 是 `lru_cache` 进程单例——跨循环复用 keepalive 连接，连接的 transport 绑在已关闭的循环上 | 会议开始后第一轮发言失败：`Agents-A1：RuntimeError: Event loop is closed`（02:23:57 网关日志）；影响所有模型调用/搜索/webhook 与后台作业交错的时刻 | `get_http_client` 改为按运行中事件循环作用域（`WeakKeyDictionary` keyed by loop）；`_with_fresh_engine` 收尾关闭本循环客户端 |
| **B-080/B-003** | **任务暂停/恢复死路**：LLM 返回后只查 CANCELLED 不查 PAUSED，`execution.status` 无条件覆盖 completed → 恢复时找不到 paused 执行 → 任务 RUNNING 无 worker 永久假恢复；另有 `_chat_stream` 未捕获 `database is locked`（busy_timeout 15s 被长写事务耗尽） | 代码推演 + 回归验证；`database is locked` 在实测对话中真实抛出（16s 后 500） | LLM 返回后尊重 PAUSED（结果存检查点、状态不覆盖）；写回前对执行行 CAS；队列满回滚任务状态 |
| **B-041** | **会话发消息 100% 崩溃**：`_conv_owned(db, user.id, cid)` 传参错位，`'str' object has no attribute 'id'` | 代码实锤（同文件其他端点均传 user 对象） | 改传 user；顺带修复 B-065（发件人身份可伪造 → 身份绑定校验） |

## 五、修复记录

**42 项修复**，全部带回归验证（最终轮：pytest 1132 项 0 失败；修复轮曾出现 3 个测试失败——2 个是测试桩未跟进 `revert_to` 新签名、1 个 pyflakes 抓到的导入顺序，均已消，门禁证明有效）。关键 diff 摘要：

1. `model_gateway.py`：`_http_clients: WeakKeyDictionary[loop, AsyncClient]` 替代 `lru_cache` 单例；`aclose()` 关当前循环客户端；`background_jobs._with_fresh_engine` finally 里关闭作业循环的客户端。
2. `agent_runtime.py`：LLM 返回后检查 PAUSED → 结果写检查点直接返回；写回前 `UPDATE ... WHERE status=='running'` CAS，丢失竞态如实记事件不覆盖。
3. `tasks.py`：resume/resolve_takeover 只恢复最新 paused 执行（其余 superseded）、队满 503 + 回滚到 PAUSED、无 paused 执行改冷启动重投（测试桩同步更新 `revert_to` 参数）。
4. `workflows.py` + `workflow_runtime.py`：保存/更新双路径图校验（非 END 必须有出边、START→END 可达、有连线）；advance 收尾兜底——空 current 或全完成未达 END → FAILED（不再永久 RUNNING）；done_nodes 跳过防重放；MERGE 语义明确化。
5. 越权组：8 个文件补归属断言（learning/team_builder/war_room/context/skill_growth 部分端点/meetings/growth_center/projects/budgets）。
6. `agents.py`：抽出 `_clear_agent_references()`，单删/批删共用（单删失败 409 不再 500）。
7. 前端：任务详情 applyChange 拆独立分支 + 如实反馈；绩效页 useEffect 化；批量删除重置激活公司；版本徽标注入；`PUT /workflows/{wid}` 接入。

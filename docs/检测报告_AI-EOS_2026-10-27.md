## 0. 体检结论（一句话）

**这是一个"产品完成度高于工程完成度"的项目**：功能面的广度和细节（415 个操作、103 张表、42 个页面、六维计量、断点续跑、审批门）在同类自托管项目里属第一梯队，前端 `tsc --strict` 零报错也说明基本功在线；但**多租户边界与凭据信任链存在可实测复现的致命漏洞，三条自家质量护栏测试正处于红灯状态，且 README 有多处对外宣称与代码不符**。当前形态适合"单机单老板"自用，**不具备公网/局域网多用户部署条件**。

## 1. P0：阻断级问题（全部有实测复现或确定性证据）

### P0-1 空 `JWT_SECRET` 接受空密钥签名 → 零口令伪造任意用户身份 ⚠️ 最严重

- **证据（实测）**：`.env.example:29` 写的是 `JWT_SECRET=`（空值）；`packaging/start-mac.sh` 与 `desktop/main.cjs` 均不生成密钥（`grep AIEOS_ENV|JWT_SECRET desktop/main.cjs` 无命中）；生产姿态闸门只在 `AIEOS_ENV=production` 生效（`apps/api/app/core/config.py:68`）。以 `JWT_SECRET=""` 启动后，用 `jose.jwt.encode({"sub": <受害者 user_id>}, "", "HS256")` 伪造的 token 调用：
  `GET /companies → 200`（拿到受害者公司）、`GET /agents?company_id=… → 200 ['核心研发']`。攻击过程**不需要密码、不需要 refresh token**。
- **放大器**：桌面壳固定 `--host 0.0.0.0`（`desktop/main.cjs:123`），即使用户从未打开"局域网共享"，8001 端口对整个局域网可达；且注册接口匿名开放（实测 `POST /auth/register → 201`），攻击者可先注册拿到合法身份再伪造。
- **影响**：同网段任意设备 = 平台所有者。模型密钥、知识库原文、成果文件、审批策略全部失守。
- **修复**：① 首启强制生成并落盘随机密钥（部署脚本已有此逻辑 `服务器一键部署.sh:191-195`，桌面/便携版必须对齐）；② `jwt_secret` 校验：空值或等于 `_DEFAULT_JWT_SECRET` 时**无条件拒绝启动**（与 `AIEOS_ENV` 解耦）；③ 桌面默认 `--host 127.0.0.1`，"局域网共享"开关才切 `0.0.0.0`。

### P0-2 多租户边界不一致：至少 4 类跨租户读写实测成功

系统有正确的原语（`app/api/deps.py:31 assert_company_owned`、`core/permissions.py:118 ensure_capability`），但**未在所有路由强制使用**。实测（用户 B 与 A 无任何关系，B 携带 A 的 `company_id`）：

| 攻击 | 结果 |
|---|---|
| `POST /kb2/global/documents?company_id=<A>` | **200 写入成功** → A 复核文档列表出现 B 注入的"所有员工立即离职"（**向他人 RAG 语料植入提示词**） |
| `GET /kb2/global/documents?company_id=<A>` | **200 泄露** A 的"A机密财报" |
| `GET /artifacts?company_id=<A>` / `GET /artifacts/{id}?company_id=<A>` | **200 泄露** A 的成果与版本内容（同文件 `artifacts.py:232 _owned_artifact` 证明正确写法本已存在，读路径漏用） |
| `PUT /intervention/policy?company_id=<A>` | **200 写入成功** → 改掉老板审批档位（**关掉高危动作审批门**） |
| `POST /tasks` 携带 `assigned_agent_id=<A的员工>` | **201 创建成功**（`routes/tasks.py:64-70` 只校验 company 归属，不校验 agent 归属；`deps.py:47 assert_agent_owned` 已有却未用） |

对照组：`/token-budgets`、`/agents` POST、`/projects`、`/companies/{cid}` DELETE、`/agents/{aid}/chat` 均正确返回 404 —— 说明这不是设计缺陷，**是收口不彻底**。
静态扫描口径：141 个端点从 query 取 `company_id`；处理函数体内不含任何 owner 关键字的写端点 101 个（其中一部分校验逻辑在 service/engine 层，需逐个确认，已实测确认的如上表 5 类）。
- **修复**：把 `assert_company_owned` 做成**路由级默认依赖**（`APIRouter(dependencies=[...])` 或全局依赖按 `company_id` 参数名自动生效），并让现有护栏测试 `tests/test_permissions.py` 覆盖"读端点"而非只覆盖 DELETE。

### P0-3 三条自家质量护栏测试处于红灯状态（交付前显然没跑 `tools/check.sh`）

实测 `cd apps/api && uv run pytest`：
- `tests/test_code_quality.py::test_no_silent_exception_swallowing` **FAILED** —— 9 处静默吞异常：`routes/clients.py:144,153`、`routes/command.py:150`、`routes/experts.py:290,345`、`main.py:87`、`mdns_advertise.py:89,101`、`model_gateway.py:429`、`performance_engine.py:73`（全仓 `noqa: silent-except` 计数为 0）
- `tests/test_permissions.py::test_every_delete_endpoint_has_an_ownership_guard` **FAILED** —— `routes/intervention.py:321`（`delete_whitelist` 只比对请求参数里的 `company_id`，未校验调用者是否拥有该公司）
- `tests/test_api_contract.py::test_frontend_has_no_raw_fetch_outside_api_layer` **FAILED** —— 前端存在绕过 `lib/api.ts` 的裸 fetch
- **意义**：护栏机制本身是**大厂级的好设计**（AST 级检查 + 契约门禁），但"有门禁且长期红"比"没有门禁"更危险——它给了团队虚假的安全感。README 宣传"158 用例全绿"与现状不符。

### P0-4 发布功能在默认交付形态（SQLite）下必然 500

`routes/artifacts.py:293,327` 使用 `text("UPDATE artifacts SET published_at = NOW() …")`。实测 SQLite：`OperationalError: no such function: NOW`。而 `core/config.py:48` 默认数据库就是 SQLite，桌面/便携版全部用它 —— **"交付流水线"的主干动作开箱即坏**。改为绑定参数传 `datetime.now(timezone.utc)`。

### P0-5 Mac 代码签名私钥 + 明文口令入库，并写入系统级信任根

`git ls-files packaging/mac-signing/` 显示 `aieos-mac.p12`、`aieos-mac.p12.b64`、`aieos-mac.crt` 均**已提交**；`AI-EOS-Mac-trust-activate.command` 内嵌 base64 p12（`:7`）、明文口令 `-P aieos2026`（`:12`）、`security add-trusted-cert -d`（`:14`）把自签证书装成受信任根，并用已弃用的 `--deep` 重签。
**影响**：该脚本随 Release 分发给每台 Mac ⇒ 私钥事实上公开。任何拿到者可用 "AI-EOS Distribution SelfSign" 签名恶意 App，并在所有跑过此脚本的 Mac 上**绕过 Gatekeeper**。这不是代码 bug，是发布信任链设计错误。
**修复**：改为每台机器本地生成密钥（私钥永不离开本机钥匙串）+ 描述文件；或走 Tier 2 Developer ID + 公证。已入库的 p12 按"已泄露"处理。

### P0-6 会议"LLM 自动纪要/行动项"是死代码

`app/meeting_engine.py:198`（及 `:212` 重复段）把 `AgentModelConfig.id`（配置行主键）当成模型 id 传给网关，网关 `db.get(Model, mid)` 必然落空，随后被 `except Exception` 吞掉回退关键词匹配。**README 宣称的"LLM 提取决策与行动项"实际从未生效，且无任何告警。** 一行修复：取 `model_configs[0].model_id`。

### P0-7 工作流 AGENT 节点异常被回滚吞掉，实例永久挂起

`app/workflow_runtime.py:92-98`：`except Exception: await self.db.rollback()` 后隐式返回 `None`；`advance_execution:213-216` 把 `None` 当作"等待人工审批"直接 commit 返回。结果：无 FAILED 状态、无错误信息、执行卡死——与该文件头注释 "supports pause/resume/retry" 直接矛盾。

### P0-8 async 路由内做阻塞 IO，单 worker 下拖死全站

- `routes/skills.py:149-156,183-185,205-207`：`async def` 里 `urllib.request.urlopen`（10–15s 超时、多仓库串行）
- `routes/auth.py:51-53`：同步 redis 客户端（`get/incr/ttl` 全阻塞；实测无 Redis 时每次登录走异常回退路径）
- `docker/` 的启动命令未加 `--workers`，即单事件循环：**一次技能市场搜索可让全站无响应十几秒**。
- 另注：`config.py:46` 注释写着 redis_url"未实际使用，保留兼容"，与实际代码矛盾（陈旧注释会误导排障）。

## 2. P1：重要问题（择要）

**后端正确性**
1. 预算到顶自动恢复永不触发：`routes/budgets.py:168` 查 `status == "PAUSED"`，`agent_runtime.py:322` 写入小写 `"paused"` → 大小写不匹配，`resumed` 恒空。
2. 每日预算窗口用时区本地时间：`model_gateway.py:384` `_dt.now()` 与 `DateTime(timezone=True)`（`models/base.py:19`，SQLite 下存 UTC）比较，东八区日限额错位 8 小时；且 `:395-412` 先 SUM 再置 paused 属 check-then-act，并发可穿透；`:427-430` `except Exception: pass`。
3. "暂停"并未中断执行：`routes/tasks.py:179-192` 只改 DB 状态，后台协程继续烧 token；完成时 `:130` 用陈旧对象把 PAUSED 覆盖回 COMPLETED。**"从 checkpoint 续跑"实为 supersede 后整任务重跑（`agent_runtime.py:328-412`），会重复计费** —— README 的"真正断点续跑"名不副实。
4. 自愈只有一半：`background_jobs.py:161` `datetime.utcnow()` 与 PG tz-aware 列比较会 TypeError（同文件 tasks 版 `:235` 已做归一，meetings 版漏）。
5. 熔断器是进程内存（`model_gateway.py:286-312` `_FAIL_STREAK/_COOL_UNTIL`）；登录限流同样有内存回退 —— 多 worker/重启即失效，`docker compose` 需显式声明单 worker 或改 Redis/DB。
6. refresh 轮换与配对码非原子：`core/security.py:84-91`、`routes/pairing.py:87-95,124` 读-判-写无 `with_for_update`/条件 UPDATE，PG 下可并发重放（SQLite 单写锁下概率低，但官方支持 PG）。
7. 上传无体积上限：`kb2.py:195`、`assets.py:103`、`meetings.py:251`、`doc_styles.py:140` 全量 `await file.read()` 进内存（只有 `training.py:222` 限 20MB）。
8. `routes/auth.py:35` 登录失败计数字典只在同 key 重试时清理，变换 identity/IP 可无界增长。
9. 匿名可访问 `/openapi.json`（实测 312KB，完整 API 面 + 全部 schema）与 `/metrics/prometheus`（`/metrics` 404、`/metrics/prometheus` 200）—— 配合 P0-1 等于把攻击地图交给局域网。
10. 数据库变更三轨并行：`main.py:43-55 create_all` + `db/migrations.py:66 ensure_columns` 手写 ALTER + 30 个 Alembic 版本 —— 新环境 schema 来源不确定，PG 上极易漂移。
11. `routes/company_manage.py:58` f-string 拼表名进 `text()`（当前入参全为字面量，无实时注入，但属危险写法）。

**前端/客户端**
12. **密码错误 → 登录页整页重载**：`apps/web/lib/api.ts:299` 对任何 401（刷新失败后）无条件 `window.location.href = "/login"`，而登录页自身就是 `api.post("/auth/login")`（`app/login/page.tsx:65`）→ 内联错误提示来不及渲染就刷新，已输入内容丢失。这是小白用户的第一道断点，必须豁免 `/auth/login|register`。

## 3. 五视角测评

### (a) 资深开发工程师
- **好**：`tsc --strict` 零报错、Alembic 线性单 head 无分叉、404-代替-403 防枚举、`utcnow()` 统一 helper、护栏测试思路（AST 静默异常检查 + 契约门禁）在同类项目里少见；`ExecutionCheckpoint` 真落库、六维计量真落库并逐维可查（`model_gateway.py:119-127`）。
- **差**：routes 占后端 60%+ 行数且直接写 SQL（`projects.py` 50 处 `db.execute`、9 个路由含裸 `text()`）；13 个 `*_engine.py` 平铺在 `app/` 根，`app/engines/` 只有一个 README；`packages/` 全空；时区/大小写/命名不一致这类"没有单一事实源"的 bug 成串出现；核心引擎（orchestrator / meeting / workflow / failover）**零单元测试**，只有 e2e 冒烟。
- **技术债最疼的一处**：schema 三轨并行（create_all + ensure_columns + Alembic）。今天 SQLite 能跑，第一次真上 PG 就会暴露。

### (b) 资深产品经理
- **主张**（"不是聊天机器人，是数字员工工作平台"）在代码里**真有一半**：组织树、招聘/培训/绩效/晋升/离职交接、CEO 拆解并行汇总、审批门、预算护栏 —— 生命周期闭环存在。
- **失焦**：42 页面 / 103 表 / 415 操作中，war_room、factory、app_alias、autonomous、test-console、doc_styles、external_agents 属长尾演示型功能；建议收敛到 ~25 页，把资源投给核心链路的**质量保障**。
- **最大产品断点：没有输出质量闭环**。e2e 用假模型；`reflection` 是 agent 自我反思而非用户反馈；用户无法给任务结果打 👍/👎 并沉淀为回归基线。"把真实工作交给 AI"的信任前提因此不成立。
- **卖点与实现冲突**："3 人以下小团队" 需要多成员权限，而系统实际只有 OWNER；"知识库检索" 实为关键词匹配。这两条不修，口碑会在第二周崩塌。
- **值得肯定**：`docs/KNOWN_ISSUES`、口径自纠、中文可行动错误文案、免 key 演示模式（虽然 `DemoMode.tsx:4-10` 自述"纯前端演出，不写库不调模型"，标注诚实但体感有限）。

### (c) 重度使用用户
- **真本事**：六维 token/成本 + 预算到顶即停（且"到顶就停不加价"的成本哲学很成熟）、审计事件、任务重试、全局急停、批量派发四类目标、⌘K 全表跳转 + 拼音搜索、一键诊断带修复建议。这些是每天要用的东西，完成度高。
- **日常摩擦**：实时性全靠 3–8s 轮询，无 SSE/WebSocket，长任务观感差；⌘K 只能跳页不能搜实体（搜不到某个任务/员工）；跨公司切换依赖 `localStorage.aieos_active_cid` + 正则改写 query（`lib/api.ts:157-166`），多公司并行有串数据风险；长列表无虚拟化；导出与全文检索能力弱（成果只能按公司列，没有跨公司搜索）。
- **信任危机**：点"暂停"其实没停（P1-3）、点"发布"直接 500（P0-4）、会议行动项其实是关键词拼的（P0-6）—— 重度用户最先撞到的恰恰是这三条。

### (d) 小白用户
- **第一公里就断**：密码打错 → 页面刷新、提示消失（P1-12）。移动端首启白屏（P1-15）。
- **认知负担**：42 个页面 + "公司/部门/员工/项目/任务/会议/战情室/工厂/成长中心" 隐喻过载；3 步向导（约 1 分钟）之后仍需自己配模型 key 才能看到第一个真实结果，而"没配 key"与"配错了"的报错区分不清。
- **静默失败文化**：86 处空 catch + 9 处被吞异常 ⇒ 用户体感是"点了没反应"，且客服无法复现。对小白，这是比缺功能更严重的问题。
- **做对的**：中文文案质量高、错误提示带下一步动作与地址、危险操作有统一 `ConfirmDialog`（但仅约 10 个页面接入，其余删除路径不统一）。

### (e) 资深产品运营经理
- **商业化不可执行**：全代码无席位校验、无 license 激活、无水印、无试用倒计时（grep 仅命中专家模板里的 MIT 字段）。BSL 1.1 的"3 人以下免费"完全靠自觉；而**云端部署正是最该收费、却最无取证手段的场景**。六维计量是唯一能直接变现的原材料，建议尽快包装成账单/chargeback。
- **增长链路为空**：无埋点（analytics/track/posthog 0 命中）、无邀请、无反馈入口 → 漏斗不可分析，"谁在用、卡在哪"无从回答。
- **可观测性半套**：有 `/metrics/prometheus`、`/health` DB 探针、`diagnostics` 页；**无 request_id/trace、无结构化 JSON 日志、无 Sentry**（`echo=settings.debug` 还把整条 SQL 打进日志，含数据明文，`db/session.py:11`）。单用户本地部署够用，多用户云端不够用。
- **发布运维**：Alembic 链健康 ✅；docker compose 有 healthcheck 且端口绑 127.0.0.1 ✅；一键脚本无 TLS/备份/回滚 ❌；CI 无测试门禁 ❌（P0-3 因此漏出）；私有仓 + token clone 让 README 的 quickstart 对外部用户根本跑不通 ❌。
- **合规**：本地落盘 `storage/kb-originals`、屏幕截图，属敏感数据；无隐私政策/用户协议文本；备份手册专业（这点比多数早期开源项目好）。

## 4. 大厂视角的优化路线（按 ROI 排序）

### 第一梯队：1–3 天，止血
1. **信任链**：`jwt_secret` 为空或等于公开默认值 → 无条件拒绝启动；桌面/便携首启生成随机密钥；桌面默认 `127.0.0.1`，共享开关才 `0.0.0.0`；`/openapi.json`、`/metrics` 在 `debug=false` 下关闭或加鉴权。
2. **越权收口**：`assert_company_owned` 上移为路由级默认依赖；`tasks` 的 `assigned_agent_id`、`orchestrate` 的 coordinator 走 `assert_agent_owned`；`artifacts`/`kb2`/`intervention` 的读端点补归属校验；把 `tests/test_permissions.py` 从"只查 DELETE"扩到"所有带 company_id 的端点"，并**把 `tools/check.sh` 挂进 GitHub Actions 作为合并门禁**（先修 3 条红灯再挂，否则门禁第一天就红）。
3. **一行修**：`artifacts.py:293,327` 的 `NOW()` → 绑定参数；`meeting_engine.py:198,212` → `model_configs[0].model_id`；`budgets.py:168` `"PAUSED"` → `"paused"`；`model_gateway.py:384` → `_dt.now(timezone.utc)`；`background_jobs.py:161` → 与 `:235` 同样做 tz 归一。
4. **前端止血**：401 跳转豁免 `/auth/login|register`；请求层支持 `AbortController` + 轮询加"仅接受最新序列号"守卫；给 86 处空 catch 分优先级补用户可见反馈。
5. **签名私钥**：p12 从仓库与 Release 资产移除并按已泄露轮换，改为本机生成密钥。

### 第二梯队：1–3 周，收敛与可运维
6. **分层**：routes 只做参数校验 + service 调用；13 个 `*_engine.py` 归入 `app/engines/`；把 `projects.py`/`governance.py`/`war_room.py` 里的 SQL 下沉。**不要试图恢复 `packages/` 拆分**——README 那张包图应删除，或在确实拆包后再画。
7. **schema 单轨**：废弃 `create_all` + `ensure_columns`，一切以 Alembic 为准；补一次真实 PostgreSQL 演练（JSON→JSONB、Enum、`DateTime(timezone=True)+func.now()` 语义、WAL 单写锁 vs 后台线程池并发写）。
8. **正确的"暂停/续跑"**：以取消令牌真正中断执行，checkpoint 存中间步骤产物，恢复时跳过已完成步骤（现在整任务重跑 = 双倍成本，这是会直接烧钱的 bug）。
9. **异步化 + 上限**：`skills.py` 的 urllib → `httpx.AsyncClient`；redis → `redis.asyncio`；所有上传加 20MB 上限 + 流式落盘；登录失败字典加 LRU/TTL；熔断器与限流状态移到 Redis（并在文档里说明多 worker 前置条件）。
10. **可观测性**：request_id 中间件 + JSON 结构化日志 + `EXCEPTION` 带 stack；接入 Sentry（DSN 由用户自填，尊重本地部署隐私）；`diagnostics` 增"一键导出 zip（日志+schema+脱敏配置）"给客服用。
11. **核心引擎补单测**：orchestrator 拆解/汇总、failover 三档、workflow 节点失败路径、预算判定 —— 这四块是"宣称多、验证少"的重灾区。

### 第三梯队：1–2 月，产品竞争力
12. **真检索**：embedding + pgvector（或 sqlite-vec）替换 bigram，加 rerank 与引用回显——知识库是"把真实工作交给 AI"的地基。
13. **质量闭环**：任务/成果级 👍/👎 + 原因落库；沉淀评测集与回归基线；`briefing` 里加失败率/重试率维度。
14. **实时化**：执行轨迹改 SSE/WebSocket，替换 40+ 页面里的轮询。
15. **多成员落地**：`CompanyMember` 表 + ADMIN/MEMBER/VIEWER 真跑通（矩阵与 `resolve_role` 已备好，改动集中在一点，是这仓库里性价比最高的架构红利）。
16. **API 契约自动化**：从 FastAPI `openapi.json` 生成 TS 类型（openapi-typescript），消灭 191 处 `any` 与手写漂移；`check_api_contract.py` 补齐 `retry/takeover` 并改成"全部候选必须命中"。
17. **页面收敛** 42 → 25；⌘K 支持实体搜索；长列表虚拟化；输入法 composition 守卫。
18. **商业化最小抓手**：启动读取 license 文件、展示 licensor 水印、记录活跃席位数（不阻断也要可取证）；把六维计量包装成可导出账单。

2. **模型接入广度**：只有 OpenAI 兼容 + Anthropic + Gemini + 空插件目录；`plugins/` 0 文件 ⇒ 对外宣称的"插件生态"目前不存在，Dify/n8n 是几百个连接器。

# 已知问题

> 最后更新：2026-09-17。本文档此前停留在 Phase 1，部分条目已过时，现按代码实测校正。
> 工程质量类的缺陷（未定义变量 / 静默吞异常 / 接口契约错配等）已在改造中清零，
> 记录见 [../UPGRADE_NOTES.md](../UPGRADE_NOTES.md)。以下为**仍然存在**的问题。

## 一、功能与体验

1. **前端局部不自动刷新**：组织架构添加部门、协作页新建会话后需手动刷新。
   数据已正确落库，仅列表未重新拉取。改造中已为调度、员工详情等页面补了轮询与加载态，
   但**尚未统一**（缺 SWR / React Query 这类数据层）。

2. **导航信息架构未收敛**：一级业务页面 34 个、导航项 35 个平铺展示，
   新用户难以建立心智模型。建议按「组织 / 执行 / 成长 / 治理 / 资产」分为 5 组并默认折叠。

3. **Pause 只在 checkpoint 生效**：正在进行的 LLM 调用无法中途打断，
   暂停会在该步完成后生效。这与任务书「下一个安全 Checkpoint」的设计一致，
   但 **UX 上需要提示**用户「暂停将在当前步骤完成后生效」，否则会被理解为无响应。

4. **表单校验与危险操作确认不统一**：注册/登录页已做完整校验与限流，
   但其他页面的校验强度与二次确认策略不一致，需要统一梳理。

## 二、性能与扩展性

5. **单进程后台执行器**：`ThreadPoolExecutor(4)` 仅适合开发环境。
   生产建议换 Celery / Temporal。

6. **Redis 已部署但未深度使用**：当前仅保留连接配置，缓存与队列未启用。

7. **token 计量维度不完整**：`usage_ctx` 这个 ContextVar **从不 reset**，
   且 training / factory 路径只设置 scenario —— 导致六维计量中丢失 agent / company 维度。
   改造中已把计量落库失败升级为 ERROR 级别日志（财务口径缺口要能被发现），
   但**维度补齐本身尚未做**。

8. **`record_token_usage` 会中途 commit**：破坏调用方事务的原子性。
   改造中记录了日志，但重构事务边界属于行为变更，尚未实施。

## 三、安全与部署

9. **JWT 无刷新机制**：24h 过期后需重新登录。

10. **权限模型为公司级粗粒度**：缺「谁可以批准什么」的矩阵。
    跨租户越权（IDOR）已在改造中补齐并加了测试守护，但**同一公司内的角色区分**仍缺失。

11. **生产环境安全门禁已就位，但需人工确认**：
    `JWT_SECRET` 仍为占位值或 `DEBUG=true` 时，`AIEOS_ENV=production` 会**拒绝启动**
    （改造新增）。请用 `openssl rand -hex 32` 生成真实密钥。

## 四、工程质量（下一步方向）

12. **尚未做真实的端到端试跑**：所有验证都是离线可重复的（117 个用例、契约、类型、lint），
    但还没有用真实模型密钥跑通「建公司 → 下达目标 → 员工执行 → 产出报告」这条主链路。
    这是判断「能否直接去用」的最后一道关，**建议优先做**。

13. **前端大量 `any`**：`api.get<T>()` 已支持泛型，可逐步替换，
    让接口契约错误在编译期就暴露，而不是等到运行时。

14. **功能广度远超可交付深度**：354 个端点 / 94 张表。
    建议收敛到 3–4 条真正跑通的完整链路，把深度做出来，而不是继续铺广度。

15. **无成功率度量**：当前只有 token 用量，没有任务成功率的真实统计，
    因此无法回答「这个系统到底靠不靠谱」。

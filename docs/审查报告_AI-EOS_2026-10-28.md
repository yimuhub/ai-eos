## 二、并发与异步正确性

### C1【P0 ✅】SQLite 写事务横跨 LLM 调用，且没有 `busy_timeout` → 并发必现 `database is locked`

**位置**：[`apps/api/app/api/routes/agent_chat.py:153-154`](../apps/api/app/api/routes/agent_chat.py#L153) → `:486`；[`apps/api/app/agent_runtime.py:166-197`](../apps/api/app/agent_runtime.py#L166)；[`apps/api/app/db/session.py:18-24`](../apps/api/app/db/session.py#L18)

```python
    db.add(msg)
    await db.flush()                    # 这里 pysqlite 隐式 BEGIN，拿到写锁
    ...
    await db.commit()                   # 第 486 行才提交，中间套了 4~5 次模型调用
```
```python
@event.listens_for(engine.sync_engine, "connect")
def _sqlite_pragma(dbapi_conn, _):
    cur.execute("PRAGMA journal_mode=WAL")
    cur.execute("PRAGMA foreign_keys=ON")      # 没有 busy_timeout
```
SQLite 在 WAL 下**只允许一个写者**；sqlite3 默认 busy timeout 5 秒。一个请求在 LLM 上挂 30 秒，任何并发写（另一路会话、后台会议、调度器 tick）等 5 秒后直接 `OperationalError: database is locked` → 接口 500。单人也能复现：网页发消息时后台任务正在写状态。

**附带问题**：`background_jobs._make_session_factory`（[background_jobs.py:43-50](../apps/api/app/background_jobs.py#L43)）新建的引擎**没挂这个 PRAGMA 监听器**，后台连接的 `foreign_keys` 实际是 OFF —— 外键约束只在主连接生效，后台路径会产生孤儿数据。⚠️（子审查定位，未逐字回读）

**修法**：`PRAGMA busy_timeout=15000` + `connect_args={"timeout": 15}`，并把 PRAGMA 抽成 `_apply_sqlite_pragmas(conn)` 供后台引擎复用；业务侧拆成「短写 → LLM → 短写」，调用模型前先 `commit()` 释放写锁。

### C2【P0 ✅】审批决策无 CAS：双击/重试/双端会**重复执行高危命令**与对外发送

**位置**：[`apps/api/app/api/routes/intervention.py:191-262`](../apps/api/app/api/routes/intervention.py#L191)

```python
    if req.status != "PENDING":
```

### D2【P1 ✅】批量删除在 savepoint 内调用 `db.rollback()`，会把此前成功的删除一起回滚，但计数仍报成功

**位置**：[`apps/api/app/api/routes/task_dispatch.py:237-274`](../apps/api/app/api/routes/task_dispatch.py#L237)（`agents.py:336-352`、`projects.py:455-460`、`departments_batch.py:120-132`、`offboarding.py:172-179`、`company_manage.py:111-125` 同型）

```python

    async with db.begin_nested():
        ...
        await db.delete(t)
    deleted.append({"id": tid, "title": t.title})
except (IntegrityError, DBAPIError) as e:
    failed.append(...)
    await db.rollback()        # 回滚的是整个外层事务，不是 savepoint
```
`begin_nested()` 本是 savepoint，异常穿出交给上下文管理器即可单独回滚；显式 `db.rollback()` 撤销了前面所有成功项，而 `deleted` 列表照旧把它们报成成功。PG 上事务还会进入 aborted 状态，后续 `log_event` 继续报 `InFailedSqlTransaction`。`company_manage` 单事务内吞异常后继续 → PG 上最后 COMMIT 实际变 ROLLBACK，`deleted_count` 却已累加。

**后果**：前端类型只能手写；后端把 `string` 改成 `object`、422 的 `detail` 变成数组，门禁全绿；调用方必须按端点特判错误。

**修法**：逐端点补 `response_model`；统一 `AppError{code,message,details,trace_id}`；契约工具解析 response schema 与前端类型比对。

### M7【P1 ✅】URL/方法一致性：两个 GET 带写副作用，`company_id` 双通道

**位置**：[`apps/api/app/api/routes/pairing.py:77,124-127`](../apps/api/app/api/routes/pairing.py#L77)、[`apps/api/app/api/routes/budgets.py:73,103-106`](../apps/api/app/api/routes/budgets.py#L73)

`GET /pair?token=...` 会写 `used_at` 并 commit —— 浏览器预取、历史记录、反代日志都能**真的消费掉一次性登录 token**；`GET /budgets` 列表里顺手把 `paused=True` 并 commit。另：`company_id` 141 个端点用 Query、227 处放 body，`/projects` 同时接受两者；更新同一类资源 PATCH 16 处 / PUT 9 处混用；`DELETE /schedules/{sid}` 实为归档。

**修法**：定规范（复数资源 + 连字符）；查询类 GET+query、动作类 `POST /{id}/{action}`；token 消费改 POST 且放 body/header；`company_id` 统一路径或 body。

### M8【P2 ✅】同一能力多份实现：归属校验 4 套、`ModelGateway` 在 15 个文件里 new 了 23 次

`deps.py` 有 4 个共享实现（86 处调用），另有 15 个本地 helper、**58 处内联 `owner_id != user...`**。语义已分叉：`_owned` 在 `agent_chat/kb2` 返回 `Agent`，在 `doc_styles/growth_center` 返回 `Company`，`worklogs._owned_agent` 又是第三种签名。`ModelGateway(db)` 在 15 个文件实例化 23 次（`war_room.py` 一个文件 5 次），各拼 messages/截断（`[:8000]`/`[:12000]` 共 11 处）/存用量。**S3/S5 的越权，本质上就是"抄就近模板抄错了"的产物。**

**修法**：收敛到 `app/services/access.py` 的 `require_company/require_agent/require_doc`；模型调用收敛到 `run_agent_turn(spec)`，路由不得直接 new `ModelGateway`。

### M9【P2 ✅】依赖与配置卫生

- `apps/api/requirements.txt` 只有 9 字节（`zeroconf`），Docker 走 `pip install .`、CI 走 `uv sync` → 死文件，按它装不出可运行环境；
- `duckduckgo-search>=8.1.1` 与 `ddgs>=9.15.0` 同时声明，但全仓 **0 处 import `duckduckgo_search`**（实际只用 `ddgs`）；
- `python-jose>=3.3` 未锁版本，该项目已归档（3.3.0 存在 algorithm-confusion 类 CVE，3.4.0 才修）；`passlib>=1.7`（2020 年后停更）被迫 `bcrypt<4`；
- **10 个环境变量绕过 Settings**：`AIEOS_HTTP_PORT`、`AIEOS_TASK_TIMEOUT_S`、`AIEOS_STUCK_TASK_MINUTES`、`AIEOS_SCREENSHOT_DIR`、`AIEOS_KB_UPLOAD_DIR`、`AIEOS_LOG_DIR`、`AIEOS_LOG_LEVEL`、`AI_EOS_MDNS`、`ProgramData/AppData`；
- 端口靠 `bind(8001)/bind(8000)` 猜"谁在监听"（`mdns_advertise.py:42-51`），多实例机器会广播错端口；20 处硬编码 timeout 字面量。

**修法**：删 `requirements.txt`；移除 `duckduckgo-search`；迁 `PyJWT` + `pwdlib[argon2]`（或直接用 bcrypt）；上述 env 全部进 `Settings`；端口与超时配置化。

# 二次调研：行业包深化与商业交付差距清单（V6.1 规划输入）

- 日期：2026-11-17
- 方法：① 10 行业逐项调研（40 次检索，主流 SaaS 模块/老板高频动作/合规罚点/集成目标四问，报告见 `docs/调研_行业包二次深化_代理报告_2026-11-17.md`）；② 平台侧调研（中国市场格局、国际标杆、MCP 生态、合规、可观测性、计费模式，7 组检索）；③ 对照 v6.0.0 已落地代码。
- 结论标注沿用：[核实]=有检索来源；[推断]=行业常识推理；[未能核实]=需进一步确认。

---

## 0. 一页结论

v6.0.0 把「基座」立住了（总线/插件/连接器/指标/安全），但**行业包是框架级不是交付级**：每个包 3 个工作流、4 个员工、9-10 个无数据源的指标——离"老板买回去每周真的在用"还差一层。调研显示缺口高度收敛为五类**平台级能力**（证照台账、对账引擎、线索生命周期、工资/分佣引擎、连接器蓝图），补齐后 10 个行业包按模板升级即可，不需要逐行业重做。

**最大的三个差距**：
1. **合规是硬门槛不是加分项**——2026-06 三部门发文 AI 智能体备案（大模型备案/算法备案/内容标识）；各行业还有自己的罚则级条款（食品进货查验、农民工工资专户、预收费存管、病历保存年限）而我们包里几乎零体现 [核实]；
2. **指标没有数据源就没有产品**——平台数据（电商三平台/美团/医保/电子税务局/G7）全部需要 ISV 资质 + OAuth 托管授权，连接器层没这个设计，交付后指标只能人工填报 [核实]；
3. **商业基础设施缺位**——可观测性（tracing→evals）、计费引擎（Agentforce 已进化到按结果付费 $2/次解决）、数据迁移交付（Datafold 的"固定价+保证结果"模式）都没有 [核实]。

## 1. 平台级共性缺口（一次建设，十行业受益）

按优先级分级。P0 = 不做就没法商业交付；P1 = 决定产品力；P2 = 锦上添花。

### P0-1 证照与合规台账引擎（跨行业共性缺口 #1）
- **事实**：每个行业都有罚则级证照——食品经营许可+进货查验记录（食安法 53 条，保存保质期+6 个月）、诊所病历 15 年/住院 30 年+处方分类保存、建筑农民工工资专户（签约 30 日内开立+总包代发+实名考勤）、物流三证年审+JT/T794 终端接入、特种设备届满前 1 个月定检、教培预收费≤3 个月/60 课时+存管账户+全国监管平台 [核实]。
- **现状**：10 包无一有「证照台账+到期预警+续办工作流」；合规内容只有零星 KB 主题。
- **动作**：平台新增 `ComplianceLedger` 实体（证照名/编号/发证机关/有效期/年审规则/责任人），**到期预警进 briefing 与 automation**；行业包 manifest 增加 `compliance_items` 段；体检/巡检类工作流模板化。
- **平台合规**：智能体备案材料包（算法说明、内容标识实现、用户协议/隐私政策模板）+ 拟人化服务办法要求的能力清单落成产品开关 [核实]。

### P0-2 对账引擎（跨行业共性缺口 #2）
- **事实**：对账/催收/现金流只在 3 个包有；零售催收、外卖佣金对账、电商平台费对账、教培预收费监管对账、建筑工资专户对账全缺 [核实]。
- **动作**：规整层新增 `ReconciliationRun`（两源对账：vouchers ↔ connector 外部流水；差异项 → 催收/整改工作流）。这是 canonical 层的自然延伸，量大但结构清晰。

### P0-3 连接器蓝图与 OAuth 托管（跨行业共性缺口 #5）
- **事实**：平台数据源全部需要 ISV 注册+商家 OAuth（淘宝/拼多多/抖店开放平台）；美团/饿了么、医保电子处方中心（动态二维码，截图结算即违规）、电子税务局（数电票/乐企）、G7、58/贝壳同构 [核实]；聚水潭/金蝶/用友/钉钉开放平台 API 齐全，**钉钉已有官方 MCP server** [核实]。
- **现状**：connector SDK 支持 Bearer/签名骨架；无 OAuth 托管流（授权回调/token 刷新/失效告警）；无 ISV 资质运营计划。
- **动作**：① OAuth 托管流进 connector SDK（v6.1）；② 每行业包 manifest 增加 `integration_targets` 段（系统名/资质要求/数据入口）；③ 平台市场页给「官方 MCP Server」优先展示（Odoo20/ERPNext/钉钉）；④ ISV 资质按行业分批申请（电商三平台先行）。

### P1-4 线索生命周期（跨行业共性缺口 #3）
- **事实**：10 包全部从「已有客户」开始，每包 roster 都有 BD/顾问角色却无线索-商机-转化流程；商业 SaaS 恰把获客当首要卖点 [核实]。
- **动作**：canonical 新增 `lead` 实体 + 通用「线索→跟进→转化→首单」工作流模板（行业包只做参数化：话术/渠道/转化周期），agent_roster 的 BD 角色绑定工作流。

### P1-5 工资/分佣引擎（跨行业共性缺口 #4）
- **事实**：计件工资（制造）、实名制工资专户（建筑）、课酬（教培）、司机承包结算（物流）、ACN 分佣（房产）——「人的钱」只有字段没有流程 [核实]。
- **动作**：平台 `PayrollRule`（计件/计时/提成/分佣四种模式）+ 月度核算工作流 + 输出对接工资专户/代发。不追求完整 HR，只做「老板算得清、发得出、有留痕」。

### P1-6 可观测性与评测（生产标配）
- **事实**：2026 行业标准是 tracing→evals→guardrails（Langfuse/LangSmith 类），要能回答「哪一步错了、这次为什么差、回滚哪个版本」[核实]。
- **现状**：有 event_log + token_usage + 绩效中心（成功率/耗时），缺**步骤级 trace 链**（LLM 调用↔工具调用↔工作流节点的同一 trace_id 串联）与评测集回归。
- **动作**：统一 trace_id 贯穿（任务→执行→工具→模型调用），绩效中心升级为 trace 查看器；评测集（docs/评测集.md）跑进 CI。

### P1-7 计费引擎
- **事实**：Agentforce 四种模式（$0.10/action、$2/会话、按席位、**按结果付费**）；Zendesk 跟进 $1.50/自动解决 [核实]。我们的 token_usage/budgets 是现成计量底座。
- **动作**：v6.1 先做「消耗报表 + 公司配额产品化」（计量→套餐→超额策略）；按结果计费等有客户案例再说。

### P2-8 交付与迁移包
- **事实**：Datafold「固定价+保证结果」的迁移服务是商业交付新模式 [核实]；SMB 交付成败在「第一个月用起来」。
- **动作**：行业包升级为「交付包」：连接器配置向导 + 首月自动化日历（每天该发生什么）+ 验收清单。demo.py 的演示公司模式扩展为「行业演示公司」。

### P2-9 其余平台补强
- NL→指标 spec 编译器（自然语言问数落到 metric 层，不裸奔 SQL）；
- kb2 路径接入向量混合检索（当前只有 kb_engine 吃向量）；
- mcp_stdio 子进程运行时；SQLite→PG 真库回归；
- 四个前端页：连接器监控/指标中心/我的员工/审批收件箱（API 已就绪）。

## 2. 行业逐项深化（升级动作清单）

每包当前 3 工作流/4 员工/10 指标；下表列「商业交付级」必须补的前 3-5 项（全部来自代理报告 [核实/推断]）：

| 行业包 | 最尖锐缺口 → 升级动作 |
|--------|---------------------|
| 制造 | ①采购下单-催料-供应商考核闭环（现采购申请单是终点）②特种设备定检台账（届满前 1 个月法定预警）③金蝶/黑湖连接器为 MRP 提供真数据 |
| 批发零售 | ①食安法 53 条进货查验台账（尽职免责条款）②会员私域流程（企微社群/储值催耗）③批发客户月度对账催收 |
| 电商 | ①库存警戒与补货工作流（商业软件核心卖点，本包竟缺）②广告法极限词/直播违规/税务稽查三罚点进合规台账 ③平台 OAuth+ISV 授权托管 |
| 餐饮 | ①外卖运营工作流（评分/差评回复/活动）+美团/饿了么数据进日报 ②油烟/排水证照台账 ③健康证到期 30 天预警 workflow 化 |
| 建筑装修 | ①农民工工资专户全流程（罚则级）②物业申报登记+管理服务协议（每单必走）③工地影像巡查工作流（装企 SaaS 最被验证卖点） |
| 专业服务 | ①拆包：律所/代账/咨询分三包（代账量大付费强，现零覆盖）②开庭日/上诉期/时效关键期限提醒（生死级）③电子税务局/数电票集成 |
| 诊所 | ①病历/处方法定保存年限台账化 ②医保电子处方中心+电子凭证对接（动态二维码）③药耗采购-效期处置闭环 |
| 教育培训 | ①预收费限额校验+存管对账（强制）②退费工作流（监管下强合规动作）③每周学情推送（家长留存） |
| 物流货运 | ①油卡台账+百公里油耗对标+偷油稽核 ②三证年审+部标终端合规台账 ③网络货运字段预埋（等保三级/实时上传） |
| 房产中介 | ①差异化三板斧：端口数据打通/防飞单/ACN 分佣核算 ②客户个人信息管理制度（2023 新规）③不得代收代管交易资金红线写进合规台账 |

## 4. 建议路线

**V6.1（平台补强，2-3 周）**：证照合规台账引擎 + OAuth 托管流 + trace_id 贯穿 + 四个前端页 + 消耗报表。验收：任一行业包能配置一条真实证照的到期预警，并在绩效中心看到一次完整任务的 trace 链。

**V6.2（行业深化，3-4 周）**：对账引擎 + 线索生命周期 + 工资/分佣引擎 + 10 包按 §2 升级到 8-10 工作流/包。验收：选制造业+零售做两个「真客户试点」，指标全部有自动数据源。

**V6.3（商业化，与试点并行）**：计费引擎 + 行业交付包 + 智能体备案材料包 + ISV 资质申请（电商三平台先行）。验收：一个付费客户从签约到首月验收的全流程跑通。

# V5.6 升级方案：一人公司 · SOP 化 + 刹车系统 + 员工工牌

> 依据：① 14 家大厂 2025–2026 组织架构调研（`docs/research/big_co_orgs.md`）
> ② GitHub 36 个同类开源项目对标（`docs/research/oss_benchmark.md`，数据快照 2026-10-19）
> ③ AI-EOS 三个差异点锚：公司组织隐喻 / 本地桌面+局域网 / 老板审批文化

## 0. 核心判断（先说结论）

1. **开源界空白 = 我们的护城河**：36 个项目里没有一个同时做到"局域网共享 + 完整老板审批流 + 公司组织隐喻 + 本地桌面"。对标项目的短板（无人机协同审批、无组织隐喻、云优先）恰是我们的锚。
2. **大厂架构 → 一人公司**：最值得仿的是「字节（攻·业务单链）+ 月暗（攻·AI 密度）+ Anthropic（守·刹车治理）」三预设，已随本版落地为 14 个 `bigco_*` 预设包。
3. **学习点收敛为三件事**：把老板审批做**细**（工具级+事件级）、把员工成长做**实**（SOP 交付物+下班学习）、把量化做**狠**（考卷打分+ROI 证明）。

## 2. V5.6.1 计划（P0，对标 Top10 中契合度最高的 5 项）

### ① 事件流 trace + 老板事件（学 OpenHands）
- 现状：B4 有节点级 trace、B1 有 takeover，但两者是两套记录。
- 升级：统一**事件流**——Agent 每个动作=事件；老板接管=向流中插入"老板事件"（最高优先级）；回放/审计/分支同一条流。桌面全本地可存（SQLite 镜像 + PG 主库）。
- 验收：老板在 trace 面板点"从这里接手" → 注入老板事件 → 继续执行后轨迹上能看到分叉点。

### ② 工具级审批 + 免批治理（学 Cline）
- 现状：审批门在 action_type 级（computer_command/external_agent/artifact_publish）。
- 升级：细到**单个工具调用**；老板可勾"始终允许此工具"（按 工具+参数模式 白名单），防审批疲劳；**plan/act 分离**——先批计划再批执行（高危工具默认 plan-only）。
- 验收：连续 10 次同类操作只弹 1 次审批（免批后）；未免批高危操作 100% 拦截。

### ③ 护栏 tripped 熔断语义（学 OpenAI Agents SDK）
- 现状：token 预算到顶 paused（P0 已做），但"原因+现场"不够结构化。
- 升级：护栏触发=**暂停+结构化原因（tripped_reason）+现场快照（checkpoint）**，不是报错；老板"加预算"即可原状态续跑（resume 保留上下文）。
- 验收：超预算任务暂停后可一键"加 500 元预算继续"，从断点跑完。

### ④ 岗位 SOP 化：结构化交付物（学 MetaGPT）
- 现状：C2 交付流水线（审核→发布）批的是 artifact 整体。
- 升级：任务带**结构化交付物字段**（需求/设计/验收标准三段模板，按岗位类型自动套）；员工之间传"文档"不传聊天；审批批的是交付物（老板看验收标准而非聊天流水）。
- 验收：公文/报告类任务完成时自动产出"验收三件套"，老板在审批门逐项打勾。

### ⑤ 员工考核考卷（学 TheAgentCompany）
- 现状：C1 HR 看板有产出/成本，但没有"能力考卷"。
- 升级：**checkpoint 部分分**——任务拆有序 checkpoint，部分完成给部分分；内置"模拟公司任务集"（LLM 扮 NPC 客户/同事），定期给每个员工出考卷，成绩进 performance → HR 看板"能力分"列。
- 验收：对任一员工一键"出考卷"，30 分钟内出分+报告（哪项能力偏弱）。

## 3. V5.7 计划（P1，员工成长线）

### ⑥ 下班学习：agent 自编辑记忆（学 Letta）
- 员工空转期写"工作日志/经验"（sleep-time learning）；**日志变更走老板审批门**（成长也要老板点头——符合确认点哲学）；记忆 **ADD-only**（只追加+标注失效，可审计历史，不覆盖）。
### ⑦ 审批过的高置信沉淀（学 mem0）
- 老板批准过的成果/技能**自动升级为高置信记忆**；检索加多信号（语义/BM25/时间/实体）。审批文化与记忆体系双向咬合——这是别的开源项目没有的。
### ⑧ 防呆工具 ACI 化（学 SWE-agent）
- 桌面操作型工具加"限行窗口+即时反馈"（每步先试错再执行），出错率↓=token↓=护栏可放宽。

## 4. V5.8 计划（P2，局域网与协议线）

### ⑨ 员工工牌 + needs-auth 态（学 A2A）
- mDNS 广播升级为 **Agent Card**（能力清单 JSON 工牌）；任务状态机原生含 `needs-auth`（审批挂起）——局域网里"别家公司的 agent"按工牌调用你的员工时，协议层就支持挂起等批。开源空白点，先发优势。
### ⑩ 成本模型按调用类型分维
- 低价值动作（通知/围观/心跳）走规则引擎，关键岗位才上 LLM；token 护栏从"总预算"扩到"调用类型"维度。

## 5. 红线（对标反模式，明确不做）

1. ❌ 无护栏全自主循环（烧钱失控 + agent 会"改名字冒充同事"跳步）
2. ❌ 群聊式编排当主干（trace 难读、token 浪费；群聊只配当部门内部讨论节点）
3. ❌ 纯拖拽流画布当卖点（Flowise 2026-08 已归档；流程可视化必须长在"员工/审批"隐喻上）
4. ❌ 多端形态不收敛（SuperAGI 停更教训；桌面为主形态，Web/局域网是投影）
5. ❌ "复刻 Devin"红海（操作型员工要做"公司里的岗位"，不是又个 IDE 插件）
6. ❌ 记忆覆盖式更新（只追加+标注失效）
7. ❌ 学术框架代码当生产底座（借机制不借代码）
8. ❌ MCP 当静态接入（协议在演进，要有 Agent Card 发现 + 协议跟踪）
9. ❌ 审批只做任务级（老板看不见高危单点动作，审批文化落空）
10. ❌ 成本模型全 LLM（低价值动作用规则引擎）

## 6. 执行顺序与验收

```
V5.6.1（2 周）：② 工具级审批（审批文化最核心）→ ① 事件流 trace → ③ tripped 语义
                → ④ SOP 交付物 → ⑤ 考核考卷（每项都带老板确认点，拒绝 Mock）
V5.7  （2 周）：⑥ 下班学习 → ⑦ 高置信沉淀 → ⑧ 防呆工具
V5.8  （3 周）：⑨ Agent Card/needs-auth → ⑩ 成本分维
```

每项验收标准：**真实调用（LLM/工具/DB）+ 老板有可视化确认点 + 3 遍自测**。

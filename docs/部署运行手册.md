# AI-EOS 部署与运行手册（E7 交付自动化）

适用版本：`apps/api/app/version.py` 当前为 **5.15.0**。升级后以文件内实际值为准。

本手册覆盖四件事：**单机部署、Docker Compose 部署、升级/回滚、备份/恢复与演练**，并给出日志排障与监控指标清单。所有命令默认在仓库根目录执行。

---

## 0. 端口、目录与环境变量（先看这张表）

| 项目 | 单机/便携包 | Docker Compose | 说明 |
|------|-------------|----------------|------|
| API | `127.0.0.1:8001` | 宿主机 `127.0.0.1:8001` → 容器 `8000` | 容器内固定 8000 |
| Web | `127.0.0.1:8000`（便携）/ `3000`（`npm run dev`） | 宿主机 `127.0.0.1:3000` → 容器 `3000` | 浏览器访问 Web |
| SQLite | `apps/api/data/aieos.db` | 挂载 `./apps/api/data` → `/data` | 备份脚本默认路径 |
| 日志 | `AIEOS_LOG_DIR`，默认 `./logs/ai-eos.log` | `/var/log/aieos/ai-eos.log` | 按日轮转，保留 30 天 |
| 上传/产出 | `STORAGE_DIR`，默认 `./storage` | 命名卷 `api-storage` → `/app/storage` | 不在本工包备份范围内 |
| JWT 密钥 | 未配置时自动生成 `apps/api/data/jwt_secret.key`（0600） | `/data/jwt_secret.key` | **丢了 = 全员重新登录** |

> 仓库里同时存在根目录 `data/`（便携启动器布局）和 `apps/api/data/`（后端默认布局）。
> 本手册与 `tools/*.sh` 一律以 **`apps/api/data/aieos.db`** 为准；不要把它们混用。

关键环境变量（完整模板见根目录 `.env.example`）：

| 变量 | 作用 | 注意 |
|------|------|------|
| `AIEOS_ENV` | `development` / `production` | `production` 会做安全门禁 |
| `DEBUG` | 调试/文档/测试台 | 生产必须 `false` |
| `DATABASE_URL` | 默认 `sqlite+aiosqlite:///./data/aieos.db` | compose 内固定为 `/data/aieos.db` |
| `JWT_SECRET` | token 签名密钥 | 生产为空/占位值会**拒绝启动**；生成：`openssl rand -hex 32` |
| `AIEOS_JWT_SECRET_FILE` | 密钥落盘路径 | 容器为 `/data/jwt_secret.key` |
| `AIEOS_LOG_DIR` | 日志目录 | 相对路径以启动工作目录为基准 |
| `STORAGE_DIR` | 产出物目录 | 建议绝对路径 |
| `METRICS_TOKEN` | `/metrics/prometheus` 令牌 | 留空时仅回环可抓取（`DEBUG=false`） |
| `NEXT_PUBLIC_API_URL` | 前端访问的后端地址 | **构建期内联**，改了要重新 build |

CORS 不是环境变量：后端在 `apps/api/app/main.py` 里用正则放行 `localhost/127.0.0.1` 与常见内网段。公网部署请走反向代理，同源暴露 Web 与 API。

初始化配置：

```bash
cp .env.example apps/api/.env
# 编辑 apps/api/.env：至少按部署环境设置 AIEOS_ENV / DEBUG / JWT_SECRET
```

## 1. 单机部署（现有启动脚本 / 源码）

### 1.1 便携包启动器

`packaging/start-mac.sh`、`start-linux.sh`、`start-win.bat` 假定**启动脚本与 `apps/`、`data/`、`storage/` 同级**（即打包后的目录布局），会自动：

- 首次安装 Python/Node 依赖；
- 启动前把 `data/` 快照为 `data-backup-YYYYmmdd-HHMMSS`（只保留 5 份，属于兜底，不是备份策略）；
- 以 `AIEOS_JWT_SECRET_FILE=<包根>/data/jwt_secret.key` 启动 API `8001`；
- 构建并启动 Next.js `8000`，日志追加到 `logs/api.log`、`logs/front.log`。

在**源码仓库**里直接双击 `packaging/start-mac.sh` 会因为它 `cd` 到 `packaging/` 而找不到 `apps/`，请使用下面两种方式之一：

```bash
# 方式 A：按 README 手动启动（两个终端）
cd apps/api && uv sync && uv run uvicorn app.main:app --host 127.0.0.1 --port 8001
cd apps/web && npm install && npm run dev          # http://localhost:3000

# 方式 B：仓库自带的开发常驻脚本（API 8000 / Web 3100）
tools/dev-up.sh
tools/dev-down.sh
```

### 1.2 生产（systemd / 裸机）

```bash
cd apps/api
uv sync
uv run alembic upgrade head
AIEOS_ENV=production DEBUG=false JWT_SECRET="$(openssl rand -hex 32)" \
  uv run uvicorn app.main:app --host 127.0.0.1 --port 8001

cd apps/web
npm ci && npm run build
NEXT_PUBLIC_API_URL=http://<对外API地址> npx next start -p 3000
```

> 生产必须：`AIEOS_ENV=production`、`DEBUG=false`、`JWT_SECRET` 非空且非公开占位值。否则后端按设计拒绝启动。
> 前端 `NEXT_PUBLIC_API_URL` 在 `next build` 时写入产物，换地址必须重新构建。

## 2. Docker Compose 部署

### 2.1 文件与前置条件

- `deploy/Dockerfile.api`：Python 3.12 slim，两阶段，`uv sync --frozen` 按 `apps/api/uv.lock` 装依赖，非 root（uid 10001），暴露 8000，`HEALTHCHECK` 打 `/health`。
- `deploy/Dockerfile.web`：Node 20 slim，`npm ci` + `npm run build` + `next start`。**`apps/web/next.config.mjs` 没有 `output: "standalone"`，因此没有做 standalone 裁剪**；如需更小镜像，应由前端负责人先改 `next.config`。
- 根目录 `docker-compose.yml`：`api` + `web`，数据绑定 `./apps/api/data`，日志卷 `api-logs`，产出卷 `api-storage`，`depends_on: condition: service_healthy`。
- `.dockerignore`：排除 `.env`、`data/`、`logs/`、`storage/`、`node_modules`、`.next`、桌面/移动端产物。**镜像内不含任何真实密钥或数据库。**
- Compose 版本：`env_file` 使用了 `required: false`，需要 **Docker Compose v2.24+**。旧版本请先确保 `apps/api/.env` 存在，或把 compose 中 `env_file` 改成普通列表。

### 2.2 首次启动

```bash
cp .env.example apps/api/.env    # 已存在则跳过；按需填 JWT_SECRET / 模型 Key
mkdir -p apps/api/data

docker compose build
docker compose up -d
docker compose ps
```

访问：

- Web：<http://localhost:3000>
- API：<http://localhost:8001/health>

健康检查：

```bash
./tools/healthcheck.sh --web-url http://127.0.0.1:3000 --env-file apps/api/.env
```

### 2.3 配置与数据

- 密钥/开关来自 `apps/api/.env`（不存在时回退根目录 `.env.example` 的空模板）；compose 文件本身**没有任何真实密钥**。
- `DATABASE_URL` 在 compose 内固定为 `sqlite+aiosqlite:////data/aieos.db`，避免 `.env` 的相对路径落到 `/app/data`。
- 修改 `apps/api/.env` 后：`docker compose up -d`（必要时 `docker compose build api`）。
- 修改 `NEXT_PUBLIC_API_URL` 后：`docker compose build web && docker compose up -d web`（构建期内联）。
- 局域网访问时把 `NEXT_PUBLIC_API_URL` 设为 `http://<宿主机IP>:8001` 再重建 web；否则浏览器会按页面 host + 端口回退，可能指错。
- 容器以 uid/gid 10001 运行，必须能**读写** `apps/api/data`（SQLite 还会生成 `-wal/-shm` 与 `jwt_secret.key`）。Linux 首次部署前执行：
  `sudo chown -R 10001:10001 apps/api/data`（或给该目录授予等价的 ACL）。macOS Docker Desktop 的 bind mount 通常无需此步。不要 `chmod 777`。
- 停止：`docker compose down`（保留 bind mount 与命名卷）。**不要随意 `down -v`**，它会删除日志/产出卷。

### 2.4 日志

```bash
docker compose logs -f --tail=200 api
docker compose logs -f --tail=200 web
# 容器内文件日志（按日轮转）：/var/log/aieos/ai-eos.log
docker compose exec api tail -n 100 /var/log/aieos/ai-eos.log
```

## 3. 升级与回滚

> 原则：**先备份，再升级；冒烟失败立即回滚，不带病上线。**

### 3.1 升级前

```bash
git rev-parse --short HEAD
sed -n 's/^__version__ *= *"\(.*\)"/当前版本 \1/p' apps/api/app/version.py
./tools/backup.sh                     # 默认写到仓库同级 ../aieos-backups
```

记录：旧 commit、旧版本号、备份目录、执行人、时间窗口。

### 3.2 升级步骤

**源码/单机：**

```bash
# 1) 停服（避免迁移与写入并发）
#    便携包：关闭启动器终端 / kill 对应 PID；systemd：systemctl stop ai-eos-api ai-eos-web

# 2) 拉代码并装依赖
git pull --ff-only
cd apps/api && uv sync && cd ../..
cd apps/web && npm ci && npm run build && cd ../..

# 3) 迁移（SQLite 启动时也会 create_all/补列，但 alembic 仍是 schema 变更正道）
cd apps/api && uv run alembic upgrade head && cd ../..

# 4) 重启（二选一）
#    便携包：重新执行启动器
#    systemd：systemctl start ai-eos-api ai-eos-web

# 5) 验收
./tools/healthcheck.sh
```

**Docker Compose：**

```bash
git pull --ff-only
docker compose build
docker compose up -d
docker compose exec api alembic upgrade head
./tools/healthcheck.sh --web-url http://127.0.0.1:3000 --env-file apps/api/.env
```

### 3.3 升级后冒烟（缺一不可）

1. `GET /health` → 200 且 `status=ok`；
2. `GET /health/db` → 200（503 = 数据库没连上）；
3. 登录页注册/登录 → 进入主界面；
4. 打开一个历史任务/成果；
5. 新建一条测试任务并执行；
6. 日志无连续 ERROR；
7. `./tools/healthcheck.sh` 汇总无 FAIL。

### 3.4 回滚

```bash
# 1) 停服
# 2) 代码回退到升级前 commit（保留工作区改动自行 stash）
git checkout <升级前 commit>

# 3) 恢复升级前备份（脚本会先自动备份“当前库”，再校验 sha256 覆盖）
./tools/restore.sh --from ../aieos-backups/aieos-backup-<升级前时间戳>

# 4) 重装依赖 / 重建（按部署方式）
cd apps/api && uv sync && cd ../..
cd apps/web && npm ci && npm run build && cd ../..
# Docker：docker compose build

# 5) 重启并重新跑 3.3 冒烟
./tools/healthcheck.sh
```

> 数据库结构若已前进（新列/新表），回滚代码前优先恢复数据库备份；只回退代码不回退库可能因结构不匹配报错。
> `restore.sh` 不会自动重启服务，这是刻意设计：让你先看清恢复结果。

## 4. 备份与恢复

### 4.1 备份 `tools/backup.sh`

```bash
./tools/backup.sh
./tools/backup.sh --out /data/backups --db apps/api/data/aieos.db
./tools/backup.sh --db /tmp/drill/aieos.db --env /tmp/drill/.env --out /tmp/drill/out
```

参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--out DIR` | 仓库同级 `../aieos-backups` | 相对路径按仓库根解析 |
| `--db PATH` | `apps/api/data/aieos.db` | 只读，不改真实库 |
| `--env PATH` | `apps/api/.env` | 显式指定但不存在时报错 |
| `--no-tar` | 生成 tar.gz | 只保留目录 |

产物：

```text
aieos-backup-YYYYmmdd-HHMMSS/
├── aieos.db          # 0600；sqlite3 .backup 一致性快照
├── api.env           # 0600；.env 副本，内容不打印
├── jwt_secret.key    # 0600；存在才备份
└── manifest.json     # 0600；版本/时间/文件清单/sha256/来源库
aieos-backup-YYYYmmdd-HHMMSS.tar.gz   # 0600；按显式文件名打包
```

关键行为：

- 有 `sqlite3`：`sqlite3 "$DB" ".backup ..."`，随后 `PRAGMA integrity_check`，失败即非零退出。
- 无 `sqlite3`：退化为 `cp`，但若检测到**非空** `-wal` / `-shm` 会拒绝并提示先停服务。
- 归档不依赖 `--exclude`（macOS BSD tar 不可靠），只传 `aieos.db api.env jwt_secret.key manifest.json` 显式清单。
- 目录/文件默认 `0700/0600`；`.env` 与 JWT 密钥内容绝不打印。
- 任一失败都会清理未完成的临时目录并非零退出。

> 注意：`sqlite3 .backup` 可能改写 SQLite 头部的 change counter / version-valid-for 两个字段，
> 因此**备份文件的 sha256 不一定等于源库文件的 sha256**，但 `.dump` 逻辑内容一致。
> 恢复校验以 `manifest.json` 里的 sha256 为准（见 4.3 演练）。

### 4.2 恢复 `tools/restore.sh`

```bash
# 先停服务！脚本检测到 -wal/-shm 或 lsof 占用会拒绝
./tools/restore.sh --from ../aieos-backups/aieos-backup-20260101-030000

# 非交互/脚本化
AIEOS_YES=1 ./tools/restore.sh --from .../aieos-backup-....tar.gz

# 连配置一起恢复（谨慎）
AIEOS_YES=1 ./tools/restore.sh --from ... --with-env --with-jwt
```

流程：

1. 接受备份目录或 `.tar.gz`；
2. 按 `manifest.json` 的 `files` 清单逐项校验 sha256（含路径穿越/重复文件名检查），任何不符立即中止；
3. 检查目标库是否被 `lsof` 占用、是否存在 `-wal/-shm`（可用 `--force` 跳过，前提是确认服务已停）；
4. 二次确认：交互输入 `RESTORE`，或 `AIEOS_YES=1`；
5. 自动调用 `backup.sh` 备份**当前**目标库到 `../aieos-backups`（可用 `--pre-backup-out` 改）；
6. 复制到同目录临时文件 → 校验 sha256 → `mv` 原子替换 → 清掉旧 `-wal/-shm/-journal`；
7. 再次校验目标 sha256 + `PRAGMA integrity_check`；
8. 打印迁移/重启/健康检查命令，**不自动重启服务**。

参数补充：`--db`（目标库）、`--env`（目标 .env）、`--pre-backup-out`、`--with-env`、`--with-jwt`、`--force`、`--yes`。

> 灾难场景：如果当前库物理损坏到 `sqlite3 .backup` 都失败，自动前置备份会中止恢复。
> 此时先把损坏库**改名保留现场**（`mv aieos.db aieos.db.corrupt-<时间>`），目标路径不存在时脚本会跳过前置备份（会打印 WARN），再执行恢复。事后仍要保留损坏库供分析。

### 4.3 备份/恢复演练（只用 /tmp 假库，绝不碰真实库）

```bash
set -e
T=$(mktemp -d /tmp/aieos-drill.XXXXXX)
mkdir -p "$T/src" "$T/out" "$T/pre"

# 1) 造假库 + 假 .env + 假 JWT 文件
sqlite3 "$T/src/aieos.db" \
  "CREATE TABLE demo(id INTEGER PRIMARY KEY, note TEXT NOT NULL);
   INSERT INTO demo(note) VALUES('original-row');"
printf 'JWT_SECRET=dummy-not-real\nMETRICS_TOKEN=dummy\n' > "$T/src/.env"
printf 'dummy-jwt\n' > "$T/src/jwt_secret.key"
chmod 600 "$T/src/.env" "$T/src/jwt_secret.key"

# 2) 备份（显式 --db/--env，确保不会读到真实配置）
env -u AIEOS_JWT_SECRET_FILE ./tools/backup.sh \
  --out "$T/out" --db "$T/src/aieos.db" --env "$T/src/.env"

BK=$(ls -dt "$T"/out/aieos-backup-*/ | head -1)
python3 - "$BK/manifest.json" <<'PY'
import hashlib, json, os, sys
m = json.load(open(sys.argv[1]))
base = os.path.dirname(sys.argv[1])
for f in m["files"]:
    h = hashlib.sha256(open(os.path.join(base, f["name"]), "rb").read()).hexdigest()
    assert h == f["sha256"], f["name"]
print("manifest sha256 OK:", len(m["files"]), "files")
PY

# 3) 改坏数据库（逻辑改坏，保证备份脚本仍能工作）
sqlite3 "$T/src/aieos.db" "UPDATE demo SET note='CORRUPTED';"

# 4) 恢复：AIEOS_YES=1 跳过交互；前置备份写到 $T/pre
AIEOS_YES=1 env -u AIEOS_JWT_SECRET_FILE ./tools/restore.sh \
  --from "$BK" --db "$T/src/aieos.db" --env "$T/src/.env" --pre-backup-out "$T/pre"

# 5) 校验：恢复文件 sha256 == manifest；逻辑内容 == 备份
EXPECTED=$(python3 -c 'import json,sys;print(json.load(open(sys.argv[1]))["database"]["sha256"])' "$BK/manifest.json")
ACTUAL=$(shasum -a 256 "$T/src/aieos.db" | awk '{print $1}')
[ "$EXPECTED" = "$ACTUAL" ] && echo "restore sha256 OK"
sqlite3 "$T/src/aieos.db" "SELECT note FROM demo;"    # 应为 original-row
diff <(sqlite3 "$T/src/aieos.db" .dump) <(sqlite3 "$BK/aieos.db" .dump) && echo "dump identical"
```

想验证“篡改检测”：复制备份目录，往 `aieos.db` 追加一个字节，再执行 `restore.sh`，应在覆盖前报 `sha256 不匹配` 并保持目标库不变。

真实库演练前**必须复制**到 `/tmp` 后通过 `--db` 指向副本；本工包脚本不会修改真实库，但恢复脚本会覆盖 `--db` 指向的文件。

## 5. 日志与 request_id 排障

- 每个响应都带 `X-Request-ID`；客户端也可用合法格式（8–128 位 `[A-Za-z0-9._-]`）自带该头，贯穿前后端与网关。
- 日志行格式：`时间 [级别] [request_id] logger: message`。无请求上下文（启动、定时任务）显示 `-`。
- 未处理异常返回 500 时，响应头与响应体都带同一个 `request_id`。

```bash
# 用户截图/前端错误里有 request_id 时：
grep '<request_id>' apps/api/logs/ai-eos.log
# Docker
docker compose logs api | grep '<request_id>'
```

日志位置：

| 部署 | 路径 |
|------|------|
| 源码从 `apps/api` 启动 | `apps/api/logs/ai-eos.log` |
| 便携包 | `<包根>/apps/api/logs/ai-eos.log`（应用文件日志）与 `<包根>/logs/api.log`（启动器重定向） |
| Docker | `/var/log/aieos/ai-eos.log`（卷 `api-logs`） |

常用手段：

```bash
tail -f apps/api/logs/ai-eos.log
grep -E '\[ERROR' apps/api/logs/ai-eos.log | tail -50
AIEOS_LOG_LEVEL=DEBUG   # 临时提升级别后重启
```

生产默认只输出 WARNING 以上；开发默认 INFO。日志按日轮转、保留 30 天。

## 6. 监控指标清单

| 端点 | 用途 | 鉴权 |
|------|------|------|
| `GET /health` | 进程存活（容器 HEALTHCHECK 用它） | 无 |
| `GET /health/db` | 数据库连通性；失败返回 503 | 无 |
| `GET /metrics/prometheus` | Prometheus 文本指标 | 见下 |

`/metrics/prometheus` 行为（`apps/api/app/main.py` 的 `guard_ops_endpoints`）：

- `DEBUG=true`：不拦截（开发/便携默认）。
- `DEBUG=false` 且配置 `METRICS_TOKEN`：必须 `Authorization: Bearer <token>` 或 `?token=<token>`，否则 **401**。
- `DEBUG=false` 且未配置 `METRICS_TOKEN`：只允许回环地址；非回环返回 **404**（隐藏端点）。

当前代码已提供的指标（不要臆造其它名字；后续 Agent 可能新增，以实际抓取结果为准）：

| 指标 | 含义 |
|------|------|
| `aieos_up` | API 进程存活，能抓到即 1 |
| `aieos_process_start_time_seconds` | 进程启动 Unix 时间戳 |
| `aieos_db_up` | 数据库探针，1=正常，0=异常 |

## 7. 常见故障与处置

| 现象 | 先查 | 处置 |
|------|------|------|
| 后端启动即退出 | 日志里的 `[security]` / `生产环境安全配置未通过` | 生产补齐 `JWT_SECRET`、`DEBUG=false` |
| 登录后频繁掉线 | `jwt_secret.key` 是否可写/是否随容器重建丢失 | 挂载 `/data`，并备份密钥文件 |
| `/health/db` 503 | `DATABASE_URL`、`apps/api/data` 权限 | 修正路径/权限后重启 |
| 前端“无法连接后端” | 浏览器 Network 的请求地址、CORS | 设置 `NEXT_PUBLIC_API_URL` 并重新 build |
| 备份报 WAL 非空 | 服务仍在写 | 先停服；或安装 sqlite3 做在线 `.backup` |
| 恢复被拒绝 | `-wal/-shm`、`lsof` 占用 | 停服后重试；确认已停可 `--force` |
| 指标 401/404 | `DEBUG`、`METRICS_TOKEN`、来源 IP | 按第 6 节调整 |

# 术语表（用户可见文案）

> 适用范围：`apps/web` 中用户能看到的文字——页面标题、导航、按钮、表单标签、提示语、空状态、错误文案、通知。
> **代码中的历史命名不改**：数据库字段（`agents` / `artifacts` / `company_id`）、接口路径（`/warroom`）、
> 组件与类型名（`Agent`、`WarRoomDetail`）、路由与网址一律保持原样。本表只统一"用户读到的词"，
> 不要求为了术语去重命名代码或迁移数据。
>
> 代码侧的单一事实源是 `apps/web/lib/terms.ts` 的 `TERMS`，`terms.test.ts` 会校验本表与代码一致。
> 本表与 `TERMS` 的推荐词必须逐条对应；新增术语时两边同时改。

| 推荐词 | 不推荐写法 | 说明 |
| --- | --- | --- |
| AI 员工 | Agent、智能体、助手、数字员工、员工机器人 | 被雇佣、有岗位与人设的数字同事。代码/接口里的 `agent` 不改；界面上首次出现用「AI 员工」，之后同屏可简称「员工」。导航里的历史名称「Agent 团队」属于待收敛项，改动需单独排期。 |
| 任务 | 目标、指令、待办、工单 | 一件被派下去、有状态与负责人的工作。「目标」是任务要达成的结果（项目/作战室层面的字段），「指令」是人对员工说的话，二者都不能替代「任务」。 |
| 交付物 | 产出、结果、产物、成果、文件 | 员工交付的成品（报告、表格、代码）。「结果」只用于"执行返回了什么"这种泛化语境（如接口结果），不要用来指交付物。 |
| 公司 | 团队、租户、组织、企业 | 组织与计费的边界。多公司切换是产品能力，不要用「租户」这种部署术语。「团队」指公司内为某个目标临时凑的一群人。 |
| 部门 | 团队、组、事业部、科室 | 公司内稳定的组织单元，参与汇报线与部门承接。临时协作的一群人叫「团队」，不要混用。 |
| 会话 | 聊天、对话记录、线程、session | 一段连续的对话上下文（单聊/群聊/会议各算一个会话）。「聊天」描述动作可以，「会话」指对象。 |
| 工作台 | 首页、工作区、workspace、桌面 | 登录后的三栏主界面（左人、中指令、右产出）。「首页」只在"访问根路径会跳到这里"这类说明里出现。 |
| 指挥中心 | 看板、驾驶舱、总览页、Dashboard | 全局总览页（公司、员工、任务、今日动向）。「指挥中枢」是导航分组名，不作为页面名。 |
| 作战室 | 战场、作战会话、作战项目、War Room | 围绕单个目标的实时执行空间。删除确认等文案里不要写「作战会话」——它就是一个作战室。 |
| 审批 | 批准、审核、放行、确认 | 危险/外发动作的人工关卡。「批准」是审批的结果（动词），「确认」是通用的二次确认，不专指审批。 |
| 席位 | 座位、License 数、名额、账号数 | 可雇佣 AI 员工的人数额度。计费语境统一用「席位」，不要出现 License/Seat 混写。 |
| 模型 | 大模型、LLM、AI 引擎、供应商 | 具体的大模型。首次出现可写「大模型」帮助理解，同屏其余位置统一用「模型」；「供应商」指模型服务商，不是模型本身。 |

## 使用约定

1. **同一屏只用一个词**。标题、按钮、提示、错误文案指向同一对象时必须同名，不做"为避免重复"的同义替换。
2. **动词与名词分开**。「审批」是关卡也是动作；「批准/拒绝」是审批的两个结果。按钮写动词（「批准」），标题写名词（「待审批」）。
3. **错误文案带对象名**。例如「任务创建失败」，而不是「操作失败」——用户需要知道是哪类对象出了问题。
4. **英文词只保留产品名与协议名**（API Key、Token、Markdown、SOP）。其余英文术语（Agent、Artifact、Session）在界面上中文化。
5. **历史命名不回改**。发现页面仍在用不推荐写法时，随该页下次功能改动一并收敛；本表不构成批量重命名任务。

## 0. 一页结论

**一句话：骨架和主线已经真实跑通，但离「每天敢用」和「能对外收费」还隔着两层——一层是 5 个安全/正确性缺口，一层是 3 个体验断层（首次成功、长任务结果回流、会话可管理）。**

| 视角 | 评分（10 分制） | 判断 |
|---|---|---|
| 专业程序开发员 | **7.0** | 测试与门禁在水准线以上；租户收口仍有漏网，schema 演进仍是「启动补列」 |
| 资深产品经理 | **6.0** | 主线成立，但产品形态是「企业模拟器」，不是「老板要结果」 |
| 重度使用用户 | **5.0** | 会用的人能干活，但会话不可管理、长任务结果会「消失」 |

| 产品运营/商业化 | **2.0** | 有成本计量，没有计费闭环；可私有化交付，不能直接卖 SaaS |

## 1. 专业程序开发员视角：对标大厂标准

### 1.1 已经做对的（不必推翻）

- **测试是资产，不是摆设**：412 个用例走真实 ASGI、临时 SQLite，包含攻击式反向断言（`tests/test_tenancy.py`）、并发 CAS 用例（`tests/test_concurrency_guards.py`）。
- **端到端主链路可重复**：`tools/e2e_smoke.py` 用真实进程 + 假模型验证「注册→建公司→配模型→招人→下达→执行→产出落盘→计费落库」38 项硬断言，且强制临时库，不碰真实数据。
- **危险操作有护栏**：任务/工作流/会议均有 CAS 或租约；启动时恢复僵尸任务；生产环境不安全 JWT 密钥直接拒绝启动；`/metrics`、`/docs` 有环境门禁。
- **v5.14 的安装接口有事务与锁**：`setup.py:150-158` 用 PG advisory lock + 单事务，思路正确。
- **群聊成本已收敛**：一条群消息不再是「每个成员串行一次 LLM」的 32 连击，`group_chat.py:223-269` 已做两段式生成。

### 1.3 P1：结构性与工程债

1. **没有 service 层**：435 个 handler 直连 ORM（`agents.py:428` 的 `data: dict` 是典型）。风险不是「不好看」，而是**校验漂移**——同一业务规则在 5 个路由里各写一遍，漏一处就是 E1/E2。
2. **契约不可信**：`response_model` 仅 2.3%，147 处 `company_id: str = Query`，14 处 `data: dict`；错误体存在 `detail: str`、`detail: dict`、`{detail, error_type}` 三套形状。
3. **可观测性不足**：无 request/trace id；Prometheus 只有 4 个探针指标（`routes/prometheus_metrics.py`），没有任务成功率、LLM 延迟、队列深度、租户成本等业务指标。
4. **前端没有数据层**：47 个页面各自 `useEffect + fetch + setInterval`；`WorkspaceChat` 单文件 1,121 行承担四种会话形态。轮询全量替换对象，长列表每轮重渲染。
5. **文档与实现漂移**：README 仍写「三步引导」「多成员协作尚未开放」，而 v5.14 已是四步向导并落地 membership；`docs/10_KNOWN_ISSUES.md` 仍停在 354 端点/94 表。文档是交付物的一部分，漂移会直接损害专业信任。
6. **CI 未跑端到端**：`.github/workflows/ci.yml` 只跑 pytest + 编译 + tsc + vitest + 契约；`tools/e2e_smoke.py` 只在本地门禁跑。CI 也没有 PG job，而产品宣称支持 PG。

### 1.4 测试有效性：进步很大，但仍有三处「假安全感」

- **覆盖率门禁只算 `app/api/routes` + `app/core`（30%）**，engines 不计；核心的调度、任务执行、模型网关不在统计内。
- **权限静态扫描有盲区**：只识别 `company_id: Query(...)` 或 body 含 `company_id`，**路径参数和他的资源 id（performance、reflection）完全扫不到**，这正是 E1/E2 能活到今天的原因。
- **`requires_llm` 用例默认跳过**：真实模型下的「派任务→执行→交付」主链路没有自动化回归，只有假模型桩。假模型能证明「管道通」，证明不了「回答对」。

## 2. 资深产品经理视角：最深刻的整改建议

### 2.1 定位诊断：主张是「一人公司」，形态是「企业模拟器」

产品的价值主张是「老板一句话，几十个 AI 员工把活干完」。但当前实现的重心在**组织拟真**：部门树、汇报线、会议、绩效、晋升、转岗、离职交接、成长中心、复盘中心、治理审计、专家库 265 人、Agent 工厂……

结果是：
- 47 个一级页面、42 个导航项、2 套界面模式、4 种会话形态、4 步安装；
- 老板要的是「把这件事办了」，产品给的是「先建一家公司」。

**这不是功能多少的问题，是价值顺序的问题。** 对一人公司/小团队，组织拟真是**成本**，不是**收益**。

### 2.2 五个产品级问题（按影响排序）

**P1｜首次价值太远：从安装到第一份可用产出，路径太长且会断**

- 安装 4 步：账号 → 公司（行业/规模/预设）→ 组织预览 → 接模型；随后强制二选一界面模式；再自己找入口下发第一个任务。
- 新向导 `/setup` **没有免 Key 演示**（`DemoMode` 只挂在旧版 `OnboardingWizard`，见 `components/OnboardingWizard.tsx:23,307`），而 README 仍承诺「免 Key 演示模式」。
- 刷新 `/setup` 回到第 1 步；若创建已成功，刷新后被 `needs_setup=false` 直接送回登录页（`app/setup/page.tsx:206`），第 4 步上下文消失。

**建议**：把「首次成功」定义为一个可验收指标——**10 分钟内拿到第一份带来源的交付物**。为此安装必须支持「先看结果、再接 Key」：内置 3 个演示任务（写文案/做竞品简报/整理会议纪要），用假数据跑完整交付链路，用户看到成品后再接自己的模型。

**P2｜结果是「文本」，不是「可验收的交付」**

- 交付中心/成果中心存在，但缺少**交付规格**：谁验收、验收标准、版本、修改意见、来源引用。
- 搜索结果没有「证据面板」：员工说「今天 6–14℃」，用户看不到它查了哪个页面、哪一段。
- 任务失败/重跑会整任务重跑，历史版本与差异不可见。

**建议**：引入「交付单（Deliverable）」对象：`规格 → 产出 → 证据/引用 → 验收（通过/打回+意见）→ 版本`。这是从「聊天玩具」变成「生产力工具」的分水岭，也是后续按结果收费的基础。

**P3｜长任务是二等公民：跑完没人告诉你**

- 切换会话立即 abort 在途流（`WorkspaceChat.tsx:126-130`），回来只重拉 history，半截回答消失且无提示；
- 会议结束提示「纪要在后台生成」，但轮询条件是 `status === "RUNNING"`（`WorkspaceChat.tsx:334`），状态一转 COMPLETED 就停止刷新，纪要常常永远不出现；
- 作战室只轮询 4 个 running 状态（`:404`），完成后的最后一条回应可能看不到；
- 没有未读计数、没有完成通知、没有「任务收件箱」。

**建议**：以「任务/交付」为中心重构工作台：左栏是**收件箱**（进行中/待验收/已完成/失败），中栏是对话与产出，右栏是证据与版本。会话只是任务的视图，不是产品的主对象。

**P4｜组织记忆没有成为护城河**

- 知识库仍是 bigram 关键词重合度检索（README 已承认），不是向量召回；
- 没有跨会话/跨员工的全局搜索；记忆库可查但不可用于「公司大脑」；
- 员工「成长」大量是状态与分数，缺少可复用的 SOP/模板沉淀。

**建议**：先做**公司级搜索**（会话、任务、产出、知识、记忆统一检索），再做 embedding 召回。护城河不是「有多少员工」，是「这家公司积累了多少只有它有的上下文」。

**P5｜广度失控，主线被稀释**

- 42 个导航项平铺；`/command`、`/warroom`、`/projects` 三个入口都在解决「一个目标怎么落地」；`/autonomous`、`/growth-center`、`/reflection`、`/training`、`/skill-growth`、`/external-agents` 等高级能力对首年客户价值有限。
- 移动端只有 KPI/一句话/签字门/连接四个 Tab（`mobile/app/_layout.tsx:30-45`），与 Web 能力严重不对齐。

**建议**：做一次「产品减法」——
- **合并**：`/command` + `/warroom` + `/projects` → 一个「目标」对象（计划→确认→执行→验收）；
- **隐藏**：成长/复盘/治理/外部协作/测试台放入「实验室」，默认不出现；
- **推迟**：移动端先做「只读会话 + 审批 + 通知」，不做全功能。

### 2.3 三个定位选项（需要老板拍板）

| 选项 | 描述 | 优势 | 风险 |
|---|---|---|---|
| A. 单人老板的 AI 执行助理 | 只保留「下目标→拿结果→验收」，组织能力全部后台化 | 最快出价值、最贴合「一人公司」 | 客单价低，易被通用 Agent 替代 |
| B. 中小企业 AI 团队 OS | 保留组织/协作/治理，卖「管理一支 AI 团队」 | 差异化强、可卖席位 | 产品重、教育成本高，当前多成员能力未闭环 |
| C. 垂直行业交付工厂（推荐先做） | 选 1 个行业（内容营销/咨询交付/电商运营），预置公司模板 + 3 个可验收交付物 | 价值可量化、易定价、易复制 | 需要行业 know-how 与交付标准 |

**推荐路径：先 C 打穿一个行业，再把 C 的能力抽象成 A，最后用 B 承接团队客户。** 不要三条同时做。

### 2.4 北极星指标与漏斗

- **北极星**：每周「通过验收」的交付物数量 / 活跃公司。
- 激活：安装→首份交付 ≤ 10 分钟；首周完成 3 份交付。
- 质量：任务成功率、人工干预率、返工率、引用覆盖率。
- 成本：单份交付的模型成本、毛利率。
- 留存：W4 留存、每周活跃天数、自动化/定时任务启用率。

## 3. 重度使用用户视角：能不能成为日常助力

### 3.1 一天的使用切面（当前会断在哪）

早上打开工作台 → 左栏找昨天那个员工 → **会话只显示 14 条、没有搜索/置顶/未读** → 发一个长任务 → 中途去问另一个员工 → **原回答被 abort，回来消失** → 下午开个会 → 点结束 → **纪要一直不出现** → 晚上想复盘 → **找不到「今天所有产出」的统一入口**。

### 3.2 必须补的十件事

| # | 痛点 | 证据 | 建议 |
|---|---|---|---|
| H1 | 会话不可管理 | `WorkspaceSidebar.tsx:262` 固定 `slice(0,14)`、员工头像 `slice(0,6)`；无搜索/置顶/归档/未读 | 会话搜索 + 置顶 + 分组 + 加载更多 |
| H2 | 切会话吞回复 | `WorkspaceChat.tsx:126-130` 视图变化即 abort | 按会话保留流缓冲；切走提示「继续/停止」 |
| H3 | 会议纪要丢失 | `WorkspaceChat.tsx:334` 仅 RUNNING 轮询；`meetingAction` 结束即提示后台生成 | 完成后追加拉取或 SSE 推送；左栏标记「有新纪要」 |
| H4 | 作战室尾响应丢失 | `WorkspaceChat.tsx:404` 只轮询 running 状态 | 完成后再拉 2–3 次 / 事件驱动 |

### 3.3 重度用户验收脚本（建议纳入每版回归）

用一天真实工作跑一遍，全部满足才算「可日常使用」：
1. 50+ 会话下，10 秒内找到上周某员工的一段回答；
2. 长回答生成中切走再回来，内容完整；
3. 会议结束 2 分钟内能在列表看到纪要；
4. 同时开 8 个功能页，刷新后全部还原；
5. 任务失败能在收件箱看到原因并一键重试；

## 4. 小白用户视角：初次使用是否顺手

### 4.1 「首次 10 分钟」走查结果（当前会卡住的 10 步）

1. 后端未起时打开 `/setup`：可以一直填，提交才报错；
2. 第 1 步乱填后点灰色「下一步」：没有任何提示（`setup/page.tsx:1931`）；
3. 第 2/3 步刷新：回到第 1 步，全部清空（`step` 仅为 `useState`，`:225`）；
4. 第 3 步预设接口失败时静默兜底 tech，所选行业失效；
5. 创建中刷新：账号已建，却被送到 `/login`，第 4 步丢失（`:206`）；
6. 第 4 步故意填错 Key：仍显示绿色「✅ 大模型已接入」（`:1604`），失败原因缩成一行小字（`:1613`）；
7. 完成后「去工作台」→ 强制二选一界面，选经典后落到 dashboard，**没有模型缺口提示**（提示条只挂极客工作台）；
8. 发长问题后切员工：回答消失；
9. 发起会议 → 结束：纪要始终不出现；
10. 右栏开 9 个页面后刷新：只剩 8 个，当前会话回默认单聊。

### 4.2 根因不是「文案」，是三条设计原则缺失

- **真实性**：失败必须阻断，不能绿色通过。Key 测试失败应把主按钮改成「去修复 Key」，而不是允许「完成进入」。
- **可恢复**：安装过程必须能刷新、能续、能重来；至少 `sessionStorage` 持久化步骤与表单，服务端记录「已安装未接模型」状态并允许回到第 4 步。
- **可体验**：接 Key 之前必须能看见产品价值（免 Key 演示）。把 `DemoMode` 接回新向导，是投入产出比最高的一次修复。

### 4.3 界面与术语

- 「经典 / 极客」二选一对小白是纯负担：**默认给一个**（建议经典），极客模式作为开关；选择页提供一句话对照，而不是「推荐」标签却没有理由。
- 术语统一为「AI 员工」；「Agent / 能力包 / 交付物 / 作战室」在首次出现处加一句解释；「Agent 团队」改为「员工团队」。
- 登录页：已有 token 应自动续登；注册后无公司时给「建公司 / 加入公司」两个明确出口，并说明邀请方式。

## 5. 产品运营经理视角：从哪里盈利与商业化

### 5.1 商业化成熟度：2/5

| 维度 | 评分 | 依据 |
|---|---|---|
| 成本计量 | **4/5** | `TokenUsage` 六维计量 + 改价不追溯 + `TokenBudget` 熔断；`PricingConfig` 有 USAGE/SUBSCRIPTION 字段 |
| 计费闭环 | **1/5** | 无套餐/订阅/订单/支付/余额/账单/发票/试用/席位；`monthly_fee`、`included_tokens_per_month` 只存不用 |
| 多租户账户 | **2/5** | 有 `CompanyMember` 多对多与角色；无客户账户层、无邀请令牌、无席位、无 SSO |
| 交付与运维 | **3/5** | Docker/一键脚本/桌面/移动齐全；备份与升级仍手工，多客户运维成本高 |
| 合规与授权 | **1/5** | 单库逻辑隔离；无隐私政策/DPA；BUSL 明确禁止未授权 SaaS/公网/>3 人 |

**结论：当前是「可私有化交付的产品」，不是「可自助购买的 SaaS」。**

### 5.2 三种商业模式与所需能力

| 模式 | 依赖的现有能力 | 还缺什么 | 适合阶段 |
|---|---|---|---|
| **A. 私有化 License + 行业实施（首选）** | Docker、桌面、RBAC、六维计量、预算熔断 | License 激活/到期/席位取证、交付包、SLA、实施方法论 | 现在就能卖 |
| **B. 按席位/公司订阅的托管 SaaS** | 多成员、角色、逻辑隔离、用量统计 | 客户账户、邀请、席位计量、订阅账单、支付、SSO、隐私合规、租户隔离加固 | 6–9 个月后 |
| **C. 按 Token / 任务 / 交付量计费** | `TokenUsage`、`PricingConfig`、预算拦截 | 按客户/模型聚合、预充值余额、发票、限流与毛利控制 | 与 B 同步 |
| D. 白标 OEM | 桌面/私有化交付 | 品牌替换、转售授权、集中 provisioning | 有渠道后 |

### 5.3 推荐商业化路径（三步）

**第一步（0–3 个月）：卖「AI 公司落地包」，不卖软件**
- 目标客户：3–20 人的内容/电商/咨询/专业服务团队；
- 打包：私有化部署 + 1 个行业公司模板 + 3 个可验收交付物 + 2 天培训；
- 定价假设（需市场验证）：年费 ¥39,800 起，实施 ¥10,000–30,000；超 10 名 AI 员工或增加行业包另计；
- 关键：**BYOK（客户自带模型 Key）**，避免转售模型能力的条款与毛利风险。

**第二步（3–6 个月）：把交付变成订阅**
- 托管版：基础平台费 + 活跃 AI 员工数 + 交付量；模型成本透传或 BYOK；
- 行业模板包单独售卖（¥9,800/套）；
- 需要补齐：License/席位计量、月度账单导出、额度拦截、试用期。

**第三步（6–12 个月）：平台化**
- 模板/技能市场抽成；OEM 白标；企业版 SSO/审计/专属部署。

### 5.4 最小可行计费闭环（MVP，3–5 件事）

1. **License 文件**：签名 + 公司/席位/到期/功能位校验；到期降级为只读，不锁数据。
2. **席位与用量口径**：定义「活跃 AI 员工」与「交付物」计量，落库可审计。
3. **额度拦截**：复用 `TokenBudget`，增加「套餐额度」层；用尽前 20% 预警。
4. **账单导出**：按公司/员工/模型/月份导出 CSV/PDF，含合同号与税号字段。
5. **试用与转化**：14 天全功能试用 → 到期转只读；先手工转账开票，不接支付网关。

### 5.5 三个会直接毁掉商业化的风险

1. **许可证**：BUSL-1.1 禁止未授权的 SaaS/公网/超 3 人使用；对外收费必须由权利人出具商业授权文本，白标/转售需单独条款。
2. **数据与合规**：单库逻辑隔离 + 历史跨租户漏洞记录 + 存知识库原文/截屏；面向企业需隐私政策、DPA、数据删除与导出、等保/生成式 AI 备案评估。
3. **模型与搜索条款**：SaaS 共用平台 Key 转售模型能力可能违反供应商条款；免费搜索抓取第三方 HTML 有反爬与 ToS 风险，商业化前应切换为合规搜索 API 或明确由客户自担。

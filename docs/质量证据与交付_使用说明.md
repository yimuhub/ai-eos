# 质量证据与交付 使用说明

> 版本：M4（2026-11-20）｜实现：`app/report/`、`app/services/autonomy.py`、`app/eval/`｜迁移：`0033`、`0034`

## 一、单文件 HTML 报告

`GET /executions/{id}/report.html`（VIEW 权限）返回一份**自包含** HTML：

- CSS 全部内联，无 `<link>`、无 CDN、无远程图片、无 `@import`；
- 产出文本一律 HTML 转义后放进 `<pre>`，XSS 注入不会被执行；
- 断网双击即可打开，直接发群里给客户看。

内容依次是：

1. **执行摘要**：状态、起止时间、步骤数、执行次数（含返工 attempt）、闸门未过数；
2. **专家分工时间线**：节点、类型、尝试、状态、起止时间、是否被返工作废；
3. **验收结果**：每个节点每轮闸门的结论、评分、未过项（期望 / 实际）；
4. **AI 自主率**（有手记时）；
5. **各步产出**：只展示每个节点的最后一版，历史版本在时间线里可见。

实现是纯函数 `app/report/renderer.py::render_execution_report`，不碰 ORM，输入是纯 dict，便于单测。

## 二、人工介入账本与 AI 自主率

### 口径

```
autonomy_rate = AI 完成步骤 ÷ (AI 完成步骤 + 人工节点 + 手记介入)
```

- **按次数，不按工作量**——一次介入就是一次，不折算工时；
- AI 步骤：`COMPLETED` 且未作废的 `AGENT / HTTP / TOOL / TRANSFORM / SUB_WORKFLOW`；
  `WAIT`、`CONDITION`、`PARALLEL` 这类编排节点**不算**"AI 干的活"；
- 人工节点：`APPROVAL / HUMAN_INPUT` 的完成步骤；
- 手记：`workflow_manual_log` 的条数；
- **没有样本时返回 `null`**，不写 0%——否则"还没跑过"会被读成"全靠人工"。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/executions/{id}/manual-log` | 记一次介入：`node_key`（可空）、`reason`、`minutes`、`note` |
| GET | `/executions/{id}/autonomy` | 单次执行的账本 |
| GET | `/metrics/autonomy?company_id=…&days=30` | 公司口径：分母相加，不对比率求平均 |

`reason` 四选一，回答"AI 卡在哪"：

| reason | 含义 |
|---|---|
| `unsupported` | 系统做不到 |
| `quality` | 产出质量不合格，人工重做 |
| `judgment` | 需要人拍板（价值判断、对外口径） |
| `external` | 等外部系统/人（资料、确认） |

## 三、评测：多 Agent vs 单次基线

### 三层结构

```
rubric.py   确定性六维评分（结论/引用/篇幅/结构/套话/缺件），权重固定、可复算
judge.py    双向盲评：A/B 顺序互换各评一次，一致才采纳，否则 tie；评审挂了也记 tie
runner.py   评分 → 盲评 → 按模型档聚合胜率与 token 比
```

**为什么先算规则分**：模型评审本身有方差。能用规则判的先判（有没有结论、有没有来源、字数、结构、套话、缺件标记），模型只补"洞察力"这类主观分；结论不一致时宁可说 `tie`。

### 离线跑

```bash
cd apps/api
.venv/bin/python ../../tools/run_eval.py cases.json
```

`cases.json`：

```json
{"suite": "industry-research-v1",
 "cases": [
   {"key": "c1", "model_tier": "strong",
    "multi": "……多 Agent 产出……", "baseline": "……单次产出……",
    "multi_tokens": 1200, "baseline_tokens": 600}
 ]}
```

输出 Markdown 表：每个 case 的多 Agent/基线分与结论、token 比；按档汇总胜率。胜率只统计明确胜负的 case，`tie` 不进分母；没有样本时显示 `—` 而不是 `0%`。

### 存证接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/evals/compare` | 记录一组成对产出（规则评分立即算，落 `eval_runs`） |
| GET | `/evals/{run_id}` | 单条记录 |
| GET | `/evals/summary?company_id=…&suite_key=…` | 按模型档聚合胜率、token 比 |

**诚实边界（必须写进对外材料）**：

- 本仓库自带的是**评测机制**，不是"8×3 已经跑完"的结论。真实结论要用你们的模型 key 生成成对产出后跑出来；
- 规则分只能证明"结构完整、有结论、有来源"，证明不了"洞察更深"；后者必须靠双向盲评；
- 小模型档（本地 8B 一类）多 Agent 交接容易放大漂移——这是 AO 公开的结论，我们尚未用自己的数据验证，**不能当作我们的结论引用**。

## 四、跑完通知

已有 `app/services/im_webhook.py` 支持飞书 / 钉钉 / Slack / 通用 Webhook 四种 payload，事务提交后才发、失败只记 warning。

工作流完成通知默认**关闭**，显式打开才发：

```bash
export AIEOS_IM_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxx
export AIEOS_IM_WEBHOOK_TYPE=feishu      # feishu | dingtalk | slack | generic
export AIEOS_WORKFLOW_NOTIFY=1           # 打开工作流完成通知
```

钉钉/飞书加签用 `AIEOS_IM_WEBHOOK_SECRET`。默认关闭是为了不改变已经配置了 IM 通知的存量部署的推送量。

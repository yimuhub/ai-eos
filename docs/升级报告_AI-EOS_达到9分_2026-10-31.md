# AI-EOS 五维度冲刺 9 分：差距诊断与升级执行报告

> 基准：v5.14.0（`065a04f`）｜ 配套：《审查报告_AI-EOS_2026-10-31.md》
> 目标：专业开发、资深产品、重度用户、小白用户、商业化运营 **五个维度同时 ≥ 9.0/10**
> 原则：**不重写、不铺新功能，在现有主线上补证据链**；UI 级调整先出静态原型再动代码。

---

## 0. 先说结论

**从 5–7 分到 9 分，缺的不是功能数量，而是「可被第三方验证的证据」。**

9 分不是「我们自己觉得好」，而是每一分都有一份可复核的凭证：渗透报告、租户隔离矩阵测试、迁移回滚演练、真实模型评测集、可用性看板、付费客户与毛利数据。没有证据的 9 分，在客户尽调、融资尽调或安全评估时会被打回原形。

**现实判断：**
- 工程/产品/重度/小白四个维度，**在现有代码上 5–7 个月可以达到 9 分**（5 名工程师 + 1 设计 + 1 产品 + 外部法务/安全）。
- 商业化 9 分**不能只靠代码**：代码可做到「可复制销售」的 9 分能力，但最终 9 分还需要 20 家付费客户、毛利率与续费数据。报告把这两层分开定义，避免自欺。
- 如果只有 2–3 名工程师，同样目标需要 **12–15 个月**；商业化仍取决于销售与合规投入。

**最高杠杆的 8 件事（先做这些，四个维度各涨 1–2 分）：**

1. 租户隔离从「逐端点记得校验」改成「拿不到裸 `company_id`」；
2. 交付从「一段文本」升级为「交付单：规格→产出→证据→验收→版本」；
3. 长任务统一进「任务收件箱」，完成必达通知；
4. 首次成功做成「免 Key 3 分钟看到成品」；
5. 安装与失败提示做到「真实、可恢复、可行动」；
6. 建 Alembic 基线 + 启动版本校验 + 回滚演练；
7. 建真实模型评测集（50–100 个任务）+ 质量看板；
8. 建 License/席位/额度/账单的最小计费闭环。

## 1. 9 分到底长什么样：可验收的评分标准

> 每个维度给出「9 分锚点」。达不到锚点就不算 9 分，避免拍脑袋。

### 1.1 专业程序开发员 9 分

| 证据 | 门槛 |
|---|---|
| 严重缺陷 | 0 个 P0；外部渗透测试无高危 |
| 租户隔离 | 所有资源型端点由**自动矩阵测试**证明「外部用户→404」，不依赖人工 allowlist |
| 数据迁移 | Alembic 基线 + 启动版本校验；升级/回滚演练通过；SQLite 与 PG 双 CI |
| 核心链路 | 真实模型评测集 + 假模型 e2e 都在 CI；核心模块覆盖率 ≥ 70% |
| 可观测性 | request_id + RED 指标 + LLM 用量/成功率/成本；P1 故障 30 分钟内定位 |
| 接口契约 | ≥ 90% `response_model`；统一错误 envelope；`/api/v1` 版本策略 |
| 代码边界 | 路由不直接承载业务规则；单文件 < 800 行；前端统一数据层 |
| 交付纪律 | 每版有迁移说明、回滚方案、变更日志；文档与实现零漂移 |

### 1.4 小白用户 9 分

| 证据 | 门槛 |
|---|---|
| 免 Key 体验 | 3 分钟内看到一份真实成品（演示数据），并明确标注「演示」 |
| 安装成功率 | ≥ 95%；4 步均可刷新续装；失败可原地重试 |

| 认知负担 | 默认一个界面；首次不强制二选一；导航 ≤ 12 项；术语统一 |
| 引导 | 首个任务有引导；空状态都给出下一步按钮 |
| 求助率 | 首次交付无需文档/客服；NPS ≥ 50 |

### 1.5 商业化运营 9 分

**能力层（代码可交付）**

| 证据 | 门槛 |
|---|---|
| License | 签名授权 + 公司/席位/到期/功能位；到期降级不锁数据 |
| 计费闭环 | 套餐/试用/额度/超量/账单/发票导出；手工转账即可闭环 |
| 成本 | 默认 BYOK；平台 Key 可选；单客户毛利可算 |
| 账户 | 邀请成员、角色、席位计量；企业版 SSO/审计导出 |
| 隔离 | 企业采购可接受：租户隔离证明 + 渗透报告 + 独立库选项 |
| 合规 | 隐私政策、DPA、数据处理清单、等保/生成式 AI 备案评估 |
| 交付 | 单客户部署 < 1 天；升级/备份自动化；监控告警 |

**业务层（代码之外）**

| 证据 | 门槛 |
|---|---|
| 客户 | 20 家付费客户，至少 3 个行业复购/续费 |
| 经济模型 | 毛利率 ≥ 60%，CAC 回收 < 6 个月 |
| 续费 | 年续费率 ≥ 80%，NRR ≥ 100% |
| 渠道 | 至少 1 条可复制渠道（行业服务商/顾问/代理） |

> **自评口径**：能力层 9 分 + 业务层未达标 = 商业化 8 分；两层都达标才是 9 分。报告路线图会先完成能力层，再用 2 个季度做业务验证。

## 3. 五条「9 分工程」：做什么、怎么验收、要多少人周

### 工程 A｜可信架构（工程 7 → 9）｜约 27 人周

| 工包 | 内容 | 验收证据 |
|---|---|---|
| A1 租户上下文 | 新增 `TenantContext`：从 token + 成员关系派生公司；资源查询必须带租户作用域；路由不再接受裸 `company_id` 作为授权依据 | 自动矩阵测试：每个带资源 id 的端点，外部用户均 404；E1/E2 类漏洞不可复现 |
| A2 迁移体系 | Alembic 基线；启动只校验版本不自动改表；提供 `upgrade/downgrade` 演练脚本 | 空库→最新、上版→最新、最新→上版三次演练通过；PG/SQLite 双跑 |
| A3 契约统一 | Pydantic 入参/出参；≥90% `response_model`；统一错误 `{code,message,details,request_id}`；`/api/v1` | OpenAPI diff 门禁；前端错误处理只认一种形状 |
| A4 可观测性 | request_id 中间件；RED 指标；LLM 延迟/成功率/成本/队列深度；SLO 与告警 | 看板可回答「哪个租户/模型/任务在失败」；P1 故障演练 30 分钟定位 |
| A5 长任务底座 | 持久化队列（Redis + arq/Celery 或 Temporal）；幂等键；重试与死信；取消语义 | 杀进程重启后任务不丢；重复投递只执行一次；取消 5 秒内生效 |
| A6 前端数据层 | 统一 query 层（SWR/React Query）；轮询改增量/事件；关键列表 memo | 1000 条消息滚动 60fps；轮询不整页重渲染 |
| A7 CI 与测试 | CI 增加 e2e smoke、PG job、覆盖率 40%→70%；权限扫描覆盖路径参数与间接资源 | 任一 P0 类漏洞回归会红；覆盖率门禁随版本上调 |
| A8 安全运营 | 依赖扫描、密钥扫描、SAST、渗透测试；安全响应流程 | 外部渗透报告无高危；漏洞 SLA（P0 24h/P1 7d） |

## 5. 路线图：四个门禁，逐段拿分

> 每个阶段结束必须过「出口门禁」，否则不进入下一阶段。这样 9 分是**累计证据**，不是最后突击。

### 阶段 0（第 1–4 周）｜止血与首次成功

- 修 E1/E2/E3（租户 + 写锁）、`chat_groups` 约束；
- 向导持久化、Key 失败阻断、恢复免 Key 演示；
- README/known issues 同步；CI 增加 e2e；
- 权限矩阵测试生成器上线（先覆盖资源型端点）。

**出口门禁**：0 P0；小白 10 分钟走查 0 阻断；错 Key 无法完成安装。

## 9. 会拖垮 9 分目标的五件事（明令禁止）

1. **继续铺新页面/新 Agent 类型**：在收件箱、交付单、评测集完成前，新增功能一律进 backlog，不进版本。
2. **用演示数据冒充能力**：任何「演示」必须标注；任何绿色成功必须有真实测试支撑。
3. **只修表面不修根因**：租户漏洞逐个打补丁而不上 `TenantContext`，会在下一次新端点复发。
4. **UI 大改不做原型**：产品减法涉及导航与首页，必须先静态原型确认，避免返工。
5. **把商业化当纯代码问题**：没有定价验证、法务文本、试点客户，代码做到 9 分也卖不出去。

## 10. 需要老板拍板的 7 个决策

1. **楔子行业**：内容营销 / 咨询交付 / 电商运营，先选哪一个？（决定 B1/B6 的模板与评测集）
2. **团队投入**：5 人 7 个月，还是 3 人 12 个月？（决定路线图节奏）
3. **产品减法**：是否同意导航 ≤12、成长类页面进实验室、三入口合并为「目标」？
4. **默认界面**：是否取消首次强制二选一，改为「默认界面 + 极客开关」？
5. **数据隔离**：标准版共享库 + RLS，企业版独立库？还是全部独立库？（影响成本与定价）
6. **付费模式**：私有化年费 + 实施，还是托管订阅？是否接支付网关（建议先手工开票）？
7. **合规目标**：是否把等保二级/生成式 AI 备案纳入 12 个月目标？（决定 E6 预算与排期）
